# 연구 검색기: 장기 바닥 · 상승 수렴형 (2026-10-22)

**사용자 선호 차트 연구 전용**. 파인엠텍(441270)이 첫 기준 사례이며, 이후 사용자가 보내는 종목과 관찰 시점·좋아하는 이유를 이 폴더의 \`cases.json\`에 **기존 항목을 보존하며 누적**한다. 실제로 돌파한 차트만 골라 생존편향을 만들지 말고 **돌파 실패·재하락·횡보** 사례도 \`role=counterexample\`/ \`status\`에 기록한다.

## 무엇을 찾나

- 장기 하락(약 1~3년 이전 고점 대비 22% 이상 낮음)
- 3개의 **확정**된 저점이 약 1% 이상 계단식 상승
- 저항 터치 3개가 7.5% 폭 안에 있고 고점·저점 간 거리가 앞보다 20% 이상 줄어든 수렴
- 현재가가 224일선 근처/위, MA5 > MA20, MA20 5봉 전 대비 -0.5% 이상
- 최근 20일 평균 거래대금 10억 원 이상(종가×거래량 근사)
- 저항과 거리 약 -7~+1%: **2단계 돌파 대기**. 이탈/미회복 상태: **1단계 바닥 형성**. 종가 저항 +1% 돌파 + 직전 20봉 대비 거래량 1.25배 이상: **3단계 돌파 확인**.
- 위 숫자는 **연구 초기 가설**이며 파인엠텍을 실제 데이터로 통과시켰다는 의미가 아니다. 결과는 재현·대조 후 조정한다.

## 주말 실행

기존 \`scripts/research/fetch_naver_daily_cache.py\`로 만들어둔 로컬 \`naver/<6자리코드>.json\` 일봉 캐시를 재사용한다. **스크립트는 인터넷 접근·데이터 수집·운영 VM 접근·주문을 전혀 하지 않는다.** 캐시가 없으면 먼저 허가된 경로로 연구 데이터를 준비하되, 캐시 원본을 Git에 올리지 않는다.

\`\`\`bash
python scripts/research/rising_base_scan.py --cache-dir /local/research/naver --out-dir /local/research/rising-base-out
python scripts/research/rising_base_scan.py --cache-dir /local/research/naver --out-dir /local/research/rising-base-asof --asof 2026-10-21 --evaluate
python -m unittest discover -s test -p 'test_rising_base_scan.py'
\`\`\`

결과: \`results.json\`(후보·단계·근거·관찰 사례·실패 입력·사후 결과), \`candidates.csv\`(후보 목록). 후보 없으면 비어 있을 수 있고 **일봉 없으면 파인엠텍은 미확인**이라고 나온다. \`--asof\` 없이 각 종목 캐시의 마지막 날짜를 쓰면 기준일이 다를 수 있으므로 비교 시 \`asof\`와 실제 일봉 날짜를 같이 본다. \`--evaluate\`는 입력 캐시에 **그날 이후 데이터가 있을 때만** D5/20/60의 다음날 시가→종가 수익률·MFE·MAE를 기록한다. 수수료·미끄러짐·체결·상장폐지·액면분할 조정·정지·유동성은 보장하지 않는다.

## 기존 코드와 비교

기존 \`scripts/cloud-vm/ascending_triangle.py\`와 \`ascending_triangle_scan.py\`는 **저점 상승·저항 수렴 후 저항 돌파**를 감지하는 수동 검색/백테스트이다(2026-08-21). 이번 것은 **장기 조정·224일선 회복·돌파 이전 단계**까지 연구하려고 구분했다. 향후 동일 후보를 두 정의에 넣고 검색률·돌파 전 적중률·거짓 양성·나쁜 결과 사례를 비교한다. 기존 5개 운영 검색기, \`daily_scan_cache.json\`, 9Pay A/B 신호, VM 작업 예약, Windows 실계좌 엔진 **모두 변경·연결 금지**.

## 종목 추가 기록 방법

1. 사용자가 **종목명 또는 종목코드와 차트·날짜**를 보내면 \`cases.json\`의 \`cases\`에 **중복 코드+관찰일을 확인**해 새 관찰을 추가한다(기존 판정 삭제 금지).
2. 관찰 근거는 \`features\`에, 사후 결과는 나중에 \`status\`/ \`note\`를 수정하거나 별도 항목에 기록한다. 좋아하는 종목과 실제 수익성은 구별한다.
3. 매주말 기존 사례 + 새로운 종목을 함께 돌려 **선호 사례/비선호 대조군, 1·2·3단계, 검출 실패 이유, 이후 5/20/60봉**을 비교한다.
4. **한 종목에 맞춘 조건 맞추기 금지**. 기존 코드의 임계값을 바꾸려면 먼저 기존 전 사례에 돌려 전·후 성적을 함께 보존한다.
