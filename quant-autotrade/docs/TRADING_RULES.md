# 자동매매 매매규칙 — 단일 기준 문서

## 확정 UI/Shadow 계약의 주문 경계 (2026-10-28, 운영 미적용)

신규 `mode=shadow`/`orderAuthorized=false`/`signalReview`는 주문 자격이 아니다. 기존 PC 수신기·최종 주문 어댑터는 이 계약을 거부한다. 기존 A/B만 별도 위험 검사를 거치며 진입/자금/청산 수치는 유지한다. [통합 검증 명세](../../docs/NINEPAY_INTEGRATED_CONFIRMATION.md).

> 기준일: 2026-10-27 KST. 이 문서는 **GitHub 코드·승인 이력의 기준표**이며 실제 PC에 설치·실행 중인 규칙의 증명이 아니다. 값의 정식 실행 근거는 소스와 해당 PC 설치본을 함께 대조한다.
>
> 규칙 변경은 실계좌 주문 활성화와 다르다. **이 문서의 작성·변경만으로 PC 스위치·승인 파일·실주문을 변경하지 않는다.** 코드 PR #1036은 GitHub 코드 반영과 별개로 VM·PC 배포 및 실계좌 적용을 확인해야 한다.

## 1. 신규 매수 우선순위 (PR #1036 코드 기준; 운영 PC 미확인)

1. **단타 (DAY)**: 장중 9Pay `ab70-v1` A/B 실시간 신호. 기존 매도 점검 뒤 가장 먼저 처리한다.
2. **스윙 (SWING)**: 전 거래일 확정 후보의 `pullback`, `doubleBottom`, `invHeadShoulders`.
3. **중장기 기술형 (LONG_TECHNICAL)**: `maCloudBreakout`. **DART 재무 관문 `longTermQuality` 통과를 뜻하지 않는다.**

같은 종목이 여러 검색기에 나오면 **상위 그룹**의 기원을 택하고, 그룹 내부는 기존 거래대금 → 평균 유동성 → 변동성 적합도 → 20일 추세 점수 순서를 유지한다. 매핑이 없는 신규 scanner는 실거래 후보로 임의 승격하지 않고 `UNCLASSIFIED_SCANNER`로 보류한다. 신규 매수 조건을 완화하거나 미래 단타 신호를 위해 예산을 따로 예약하지 않는다.

- 실행 흐름: **30초마다 기존 보유 매도 점검 → 3초마다 9Pay 단타 조회·매수 가능 시 우선 → 해당 30초 주기의 기존 후보 매수**. 매도 판정은 같은 주기에 중복 실행하지 않는다.
- 단타로 매수가 발생하면 `PRIORITY_POOL_AFTER_DAY_BUY`에 기존 야간 연구 DB의 스윙·중장기 **원시 후보 수**만 기록한다. 이는 실제 주문 자격 통과·미체결·성과가 아니며 종목 자금을 재배분하지 않는다.
- 원천: [PC 실행 순서](../local_bot/live_runner_9pay.py), [야간 후보 순위](../local_bot/live_engine.py), [검색기 그룹](../../docs/SCANNER_FIVE_GROUPS_2026-10-19.md).

## 2. 자금·종목 수 (2026-10-22/23 GitHub 코드 기준, PC 미설치 기록)

| 항목 | 저장소 코드 기준 |
|---|---|
| 총 운용예산 `BUDGET` | 1,000,000원 |
| 최소 유보현금 `RESERVE` | 100,000원 |
| 최대 종목 수 `MAX_STOCKS` | 예산 100만 원 단위 올림 → 현재 1종목 |
| 종목당 상한 `PER_STOCK` | `(BUDGET-RESERVE)//MAX_STOCKS` → 현재 900,000원 |
| 실제 주문 수량 | `min(종목상한, 주문가능현금-유보현금, 총예산-유보현금-기점유금)//현재가` |
| 중복·점유 | 실제 보유·미체결·장부상 OPEN/PENDING과 당일 매수 의도를 고려 |

900,000원은 **고정 투입액이 아니라 상한**이다. 기존 개인 제외 종목과 주문 이력·자금 점유 처리 및 동일 계좌 사용을 유지한다. 10월 19일 PC에는 과거 정책인 **최대 종목 수 무제한·종목당 30만 원** 적용 기록이 있어, 위 최신 코드가 지금 PC에서 실행 중이라고 단정하지 않는다. 운영 사실은 [LIVE_OPERATIONS.md](LIVE_OPERATIONS.md) 참고.

## 3. 기존 검색기(야간 확정 후보) 신규 매수

- 스캔일은 전 거래일, `NEW` 상태, 해당 스캔일로 끝나는 **확정 일봉 최소 21개**가 필요하다.
- 최근 20개 일봉 평균 거래대금(종가×거래량) **10억 원 이상**, 평균 일중 고저 변동폭 **1~8%**, 마지막 종가가 20일 평균 종가보다 높아야 한다. 결측·오류·오래된 봉을 임의 보간하지 않는다.
- 종목 현재가가 기준가 대비 **+2% 이상**이면 추격 매수하지 않는다. 시세 조회값은 **180초 이내** 신선해야 한다.
- 주문은 가용현금·보유·승인·제외·STOP 및 주문 장부를 재확인한 뒤 **지정가**. 기존 엔진 신규 매수 창은 저장소 기준 **09:00~13:59:59 KST**다.

원천: [live_engine.py](../local_bot/live_engine.py)의 `rank_candidates`·`trade_once`. 연구 후보 `RESEARCH/live_eligible=0`와 실제 PC 주문 후보 소비 경로의 일치 여부는 별도 점검이 필요하며 연구 결과를 실계좌 승인으로 해석하지 않는다.

## 4. 9Pay 단타 신규 매수

- 규칙 버전 `ab70-v1`. 09:00 이후 실제 관측한 동일 공급자 누적 거래량 차이를 기준으로, **전 거래일 확정 전체 거래량의 70% 이상 유입**을 **09:00~13:59:59 KST** 안에 최초 확인해야 한다. 80% 도달도 별도 우선 정보로 기록한다. 14시까지 확대된 구간은 최초 09:00~09:29 표본과 별도의 수익성 검증이 필요하다.
- 최초 70% 충족 후 **1% 이상 눌림**, 아래 분기 중 하나: **A** 이전 고점 돌파 + 같은 소스 거래량 증가; **B** 확정 일봉 2개 저점 상승 + 갭상승 + 시가 이상에서 지지 + 저점 대비 0.3% 반등. 첫 눌림 저점을 재이탈한 무효 신호를 재활성화하지 않는다.
- 수신 계약: 신호 나이 **10초 이하**, 순위 나이 **120초 이하**, 시세/거래량 결측 없음, 공급자·A/B·버전·제외·저장/큐 누락·불완전 순위 검증. 누락 증거를 지워 매수를 재개하지 않는다.
- 최종 `ka10001` 현재가가 신호가보다 **0.3% 초과 높으면** 매수하지 않는다. PC 실주문 직전에 STOP·계좌 승인·미체결·주문 불확실성을 재검증한다.
- PR #1036은 새 **신호 발행·수신 승인·주문 실행**을 모두 14:00 이전으로 정합화한다. **15:20은 매도 점검을 포함한 엔진 상한**이며 14:00 이후 신규 단타 매수 허용이 아니다.

원천: [VM 신호 판정](../../scripts/cloud-vm/kiwoom_9pay_observer.py), [PC 수신 검증](../local_bot/ninepay_signal_client.py), [PC 주문 직전 검증](../local_bot/ninepay_trade.py).

## 5. 매도·손절·익절 (2026-10-16 사용자 승인 규칙)

| 동작 | 매입가·관측 최고가 대비 가격 변화율 (수수료 제외) |
|---|---|
| 일반 손절 | 매입가 대비 **-3% 이하**, 약 30초 간격 **연속 2회 확인** 후 매도 |
| 비상 손절 | 매입가 대비 **-5% 이하 즉시** 매도 |
| 추적 활성 | 매입가 대비 관측 최고가 **+3% 이상** |
| 추적 매도 | 활성 후 최고가 대비 **-2.5% 이하**, 연속 2회 확인 후 매도 |
| 고정 목표가 | +6% 고정 익절 상한 및 +3% 수익 바닥 **없음** |

고점 `peak_price`와 연속 횟수 `exit_hits`는 장부에 저장해 재시작에도 이어진다. **엔진 소유 포지션만** 자동 청산하며, 개인 제외 종목은 엔진이 매수·매도하지 않는다. 비용 0.7% 가정은 별도의 예상 순손익 계산에만 사용하며 위 매도 트리거에 더하지 않는다. 원천: [실제 엔진](../local_bot/live_engine.py), [10/16 청산 변경 기록](LIVE_EXIT_RULES_2026-10-16.md).

## 6. 상시 금지 및 주문 안전 게이트

- 인버스·레버리지와 CD금리·KOFR/SOFR·MMF/머니마켓·단기채·초단기·파킹 등 현금성·금리형 상품 **신규 주문 제외**. 일반 주식형·섹터 ETF 전체 금지가 아니다.
- 종목명 미확인/제외 목록 미확인, 계좌 다중/불일치, 미체결 주문, 잔고·시세 불확실, 피드 큐 누락·저장 장애·순위 결측 등에서 **신규 진입 보류**. 기존 보유의 허용된 청산 관리는 유지한다.
- `LIVE_TRADING=1`과 실제 계좌 지문·날짜에 결속된 승인 파일이 필요하다. 9Pay 단타 주문에는 `NINEPAY_LIVE_TRADING=1`도 별도로 필요하다. 실제 상태는 문서나 저장소로 확인 불가하다.
- 주문 의도(`intent`)는 증권사 호출 전에 기록하며, 불확실한 주문 응답을 자동 재시도하지 않는다. `STOP`을 우회하지 않는다.
- 계좌·비밀키·원시 주문/로그·DB·개인 경로는 공개 GitHub에 기록하지 않는다.

## 7. 문서·코드 충돌 시

1. **이 파일은 정책 탐색의 단일 기준**, 수치 계산의 실행 기준은 `local_bot` 코드, 실전 적용 사실의 기준은 실제 PC 설치본·운영 검증 로그다.
2. 오래된 `PROPOSED_SINGLE_ACCOUNT_POLICY_2026-10-13.md` 등의 +6% 고정 익절·3종목 규칙은 **당시 정책 기록**이지 최신 규칙이 아니다.
3. 연구용 `live_paper.py`의 09:30 가상 진입·독립 모의예산·ATR 청산은 **별도 모의전략**이며 이 실계좌 규칙에 섞지 않는다.
4. 실제 PC 설치, 엔진 실행·재시작·스위치, 계좌 승인·실제 주문 및 운영 정책 적용은 별도 구체적 승인과 사전 확인이 필요하다.
