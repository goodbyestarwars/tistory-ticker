# 자동매매 실계좌 운영·PC 설치 상태

## 2026-10-29 06:31 KST 승인 후 PC 적용 완료

사용자가 3파일 교체와 감시 봇 재시작을 승인해 장전 유지보수로 적용했다. 두 client와 공통 gate만 백업 후 교체했으며 설치 SHA256·구문·실제 공유 잠금 권한을 검증했다. 배포 직전 신규 오프라인 14개 재통과. 봇 재시작 후 로컬 서버와 신규 gate import를 확인했고 초기 로그 잔고 실패는 0행이었다. 실거래 runner는 실행 중이지 않아 수동 시작/재시작하지 않았으며 다음 기존 예약에서 새 client를 로드한다.

실거래 스위치·승인·STOP·NO_AUTOSTART 및 두 예약 작업 XML은 전후 동일하다. 다른 운영 Python 소스와 전략도 동일하다. 실 API를 이용한 별도 점검/주문·master 병합·VM 배포는 하지 않았다. 일반 봇 시작에 따른 기존 운영 동작은 재개됐다. 이후 장중 제한 오류·실제 체결 검증은 이번 확인 범위가 아니다. 백업과 private 적용 결과는 PC에 보관했다.

## 3. PC 읽기 전용 점검 체크리스트 (미실행)

실제 PC에서 **자동 실행·종료·재시작 없이** 담당자가 다음을 확인해 기밀값 없이 결과만 요약한다.

1. `AutotraderLiveTrading` 예약 작업의 존재/마지막 실행 결과/현재 동작 여부(스케줄 변경 금지).
2. 설치된 `live_runner.py`·`live_engine.py`·`ninepay_signal_client.py`·`ninepay_trade.py`의 Git 기준 대비 SHA-256. 경로/계정/키 값은 보고서에 공개하지 않는다.
3. **실제 로드된 엔진 상수**: `BUDGET`, `RESERVE`, `MAX_STOCKS`, `PER_STOCK`, `STOP_PCT`, `EMERGENCY_STOP_PCT`, `TRAIL_ARM_PCT`, `TRAIL_PCT`, `CONFIRM_CHECKS`, 진입 시간.
4. `LIVE_TRADING`, `NINEPAY_LIVE_TRADING` 활성 여부 및 승인 파일 존재·계좌 일치 여부는 **참/거짓만**. 비밀값/계좌 지문/원본 승인 파일 공유 금지.
5. 기존 포지션·미체결·불확실한 주문 의도·제외 목록 유효 여부와 잔고 여력. 원본 장부를 복사·초기화·재구성하지 않는다.
6. VM 건강 상태 및 현재 거래일 `queueDropped`, `persistenceError`, `rankError`, `amountFallback`, 순위 갱신 신선도. **누락 누계를 삭제해 신호를 허용하지 않는다.**

상태 확인만으로 자동매매 주문 가능 조건이 충족됐다는 결론을 내리지 않는다.

## 4. 배포 안전 절차 (현재 미승인)

- **PR 코드 검증 → 운영 영향 분석 → PC 실계좌 적용에 대한 사용자 별도 구체적 승인 → 장외 유지보수 창 → PC 설치본 백업/4파일 일괄 설치 → 해시/구문/호환성/읽기 점검 → 후속 장중 관측**.
- GitHub `master` 병합은 **PC에 자동 반영되지 않는다**. 반대로 VM `master` 배포는 시스템 재시작/피드에 영향을 주므로 VM 병합도 의도 없이 하지 않는다.
- PC의 `.env`, 승인 파일, 계좌·제외 목록, 미체결/장부, 예약 작업은 자동 변경 금지. `--run` 수동 시작도 금지.
- 잔고·주문 불확실·피드 누락 시 신규 매수는 차단하고 소급 주문·소급 재구성하지 않는다. 주문/체결·실제 MFE/MAE·수익성은 오프라인 모의 통과만으로 입증되지 않는다.
