# 실계좌 엔진 청산 규칙 변경 · 기록 추가 (2026-10-16)

대상: PC 실계좌 엔진 `live_engine.py`(저장소에는 없음, 사용자 PC `autotrader` 폴더에만 있음). 승인: 2026-10-16 사용자("1번은 진행해"). 매수 조건·종목 수·예산·진입 시간(09:00~10:00)은 **바꾸지 않았다**.

## 규칙 (모두 매입가·고점 대비 가격 변화율, 비용 제외)
| 구분 | 이전 | 이후 |
|---|---|---|
| 일반 손절 | 순손익 -5%(≈ 가격 -4.3%) 즉시 | 가격 -3% 이하가 **연속 2회 사이클**(약 30초 간격) 확인되면 매도 |
| 비상 손절 | 없음 | 가격 -5% 이하 **즉시** 매도(급락 대응, 확인 없음) |
| 익절 | 순손익 +6% 고정 상한, +3% 도달 뒤 3% 아래로 내려오면 매도 | 고정 상한·바닥 없음. 고점이 +3% 이상이 된 뒤 **고점 대비 -2.5%** 이탈이 연속 2회 확인되면 매도 |

- 고점은 사이클마다 관측한 현재가(1분봉 종가)의 최댓값이며 `positions.peak_price`에 저장해 재시작해도 이어진다. 연속 확인 횟수는 `positions.exit_hits`.
- 근거: 12건(5분봉 근사, 같은 날 청산) 시뮬에서 손절 -3%로 손절 두 건이 약 1%p씩 줄었고, 익절을 길게 가져가는 효과는 하이브 한 종목(+2.4%→+8.6%)에 크게 의존했다. 표본이 작아 방향 확인용이다.
- 제외 종목(`engine_excluded.json`)은 이전과 같이 어떤 주문도 내지 않는다.

## 기록(주문 판단에는 쓰지 않음)
- `intents.reason`·`intents.note`(JSON): 매수 = `ENTRY` + 순위·검색기·기준가 대비 진입가·점수 4요소·슬롯 수, 매도 = 사유(`STOP_3`·`STOP_EMERGENCY`·`TRAIL_2_5`) + 판정 시점 가격·수익률·고점·확인 횟수. `intents.price`에 매도 판정가도 남긴다(실제 체결가는 아님).
- `skips` 표(날짜·종목·사유별 1줄, 횟수 누적): 후보 탈락(`LOW_TRADED_VALUE`·`VOLATILITY_RANGE`·`BELOW_20D_MEAN`·`BARS_UNAVAILABLE`·`BAD_BARS`), 진입 거절(`GAP_UP_OVER_2PCT`·`PRICE_STALE`·`QTY_OR_PER_STOCK_LIMIT`·`ALREADY_HELD_OR_SENT`·`EXCLUDED`), 전체(`*`: `SLOTS_FULL`·`NO_CASH`·`BUDGET_COMMITTED`·`WINDOW_CLOSED`).
- 기존 장부는 컬럼만 덧붙이고(`ALTER TABLE`) 값은 그대로다.

## 적용
- 실행 중인 엔진 프로세스는 파이썬 모듈을 이미 읽었으므로 이날 장중에는 **이전 규칙**으로 계속 동작한다. 작업 스케줄러 `AutotraderLiveTrading`이 다음 시작할 때(다음 거래일) 새 규칙으로 뜬다.
- 로컬 봇(`bot.py`)은 새 상수·`exit_decision()`을 읽어 운영센터에 새 규칙을 보여 주며, 봇을 재시작하기 전에는 '조회 불가'로 보인다. 엔진 규칙을 읽지 못하면 값을 보여 주지 않는다.
- 백업: PC `autotrader/backup_20261016_exit_rules/`.
- 롤백: 백업의 `live_engine.py`를 되돌리면 이전 규칙이다(추가된 컬럼은 무해).
