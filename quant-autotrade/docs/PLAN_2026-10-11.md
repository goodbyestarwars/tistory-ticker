# 퀀트 자동매매 2.0 — Phase 1 검증 결과와 구조 검토 (2026-10-11)

브랜치 `feature/quant-autotrade-2`. 운영 사이트·계좌·VM 설정은 변경하지 않았다. 오프라인 분석과 UI 시안만 포함한다.

## 1. 전략 수익성 검증 (`quant-autotrade/backtest/exit_study.py`)

대상: 국내 234종목 5년 일봉(Yahoo, 생존편향 있음), 검색기 5종. 진입은 신호 다음 날 시가 지정가(+0.2%) 또는 종가, 갭 +2% 이상이면 미진입.
비용 왕복 0.4% + 청산 슬리피지 0.3%. 청산 8종(고정 −3/+5, 고정 −5/+10, ATR 손절·익절, ATR 추적, 분할 익절+추적, 기술적 손절, 5일·10일 보유).
개발/검증 분할 2024-09-20. 80개 조합을 비교하므로 통과 기준을 엄격하게 잡았다(검증 구간 평균−3.2×SE > 0 등).

**결과: 통과한 조합 0개.**

- 고정 손절·익절(−3/+5, −5/+10)은 모든 검색기에서 기준선(아무 날 진입)과 구별되지 않거나 더 나빴다.
- ATR 추적 손절·10일 보유는 검증 구간(2024-09~)에서 +1~2%로 좋아 보이지만, **같은 구간의 기준선도 +0.5~0.8%**다.
  개발 구간(~2024-09)은 대부분 마이너스다. 상승장 효과(베타)를 검색기 효과로 볼 근거가 없다.
- 같은 보유 기간 KOSPI 대비 초과수익은 상위 조합도 −0.04%~−1.2%로 음수 또는 0 근처다.
- 시장 국면(KOSPI 120일선 ±3%)별로도 일관된 우위가 없다(눌림목·추적 손절은 상승장에서만 +, 횡보에서 −).
- 이 스크립트의 MDD는 겹치는 보유를 무시한 근사라 −30~−99%로 과장될 수 있다. 판단 근거로 쓰지 않는다.

**검증하지 못한 항목:** 진입 시각별 성과(09:10~10:30 등), VWAP·5분봉 돌파, 호가·스프레드, 지정가 체결 가능성 — 분봉·호가 이력이 없다.
open/close1 비교는 거친 대용치일 뿐이다. 표본 수는 눌림목 879, 구름 돌파 1,347 수준이라 신뢰구간이 넓다.

**결론:** 현재 데이터로 자동매수에 편입할 검색기는 없다. 지시서의 기준(검증 안 된 전략은 매수 금지)에 따라 매수 엔진은 활성화하지 않는다.
ATR 추적·시간 청산 계열이 유일한 후속 연구 후보이며, 모의운영에서 실제 체결 기준으로 재검증한다.

## 3. 로컬 수집기 용량 추정 (5GB 상한)

- 1분봉 20종목×390봉×90거래일 ≈ 70만 행 → SQLite 약 50~100MB.
- 호가 10단계 스냅샷을 1초 간격으로 20종목 전 시간 저장해도 하루 약 0.1GB, 7일 보관 약 0.7GB(신호 접근 시점만 저장하면 수십 MB).
- 따라서 **5GB는 충분하다.** 병목은 용량이 아니라 키움이 과거 분봉을 얼마나 주는지, 호출 한도가 얼마인지다.
- PC 점검: 디스크 여유는 5GB 상한 대비 충분했고 메모리 여유는 약 3GB였다.
- 5GB 정책(3/4/4.5/5GB 단계, WAL·SHM·로그·백업 포함 실사용량 기준, 체결·전략 평가·주문 기록은 일반 정리에서 제외)은 설계대로 구현 가능하다. 아직 구현하지 않았다.

## 4. 클라우드 엔진 구조와 비용 (검토 의견, 가격은 공시 기준 추정이며 실제 청구 전 확인 필요)

핵심 제약:
1. 키움 앱키는 **IP 등록 방식**이다. 지금 등록된 것은 운영 수집용 VM 고정 IP와 사용자 PC의 공인 IP다(값은 문서에 적지 않는다).
2. 키움은 같은 키에 같은 토큰을 돌려준다(2026-09-17 실측). 수집 VM과 주문 엔진이 같은 앱키를 공유하면 토큰 만료·갱신 충돌(8005) 위험이 있다.
3. 현재 VM은 e2-micro(메모리 1GB)이고 GCP 장애 이력(VM 중지·리셋 금지 상태가 있었다)과 "지출 여력 없음" 제약이 있다.

| 옵션 | 월 비용(추정) | 의견 |
|---|---|---|
| A. 기존 VM에 주문 엔진 추가 | 0 | 1GB에서 수집·FastAPI·스캔과 경합한다. 같은 프로세스 권한이라 공개 API와 보안 경계가 분리되지 않는다. **비권장** |
| B. GCP e2-micro 한 대 추가 (고정 IP 포함) | 약 $9~11 (₩13,000~16,000) | 별도 앱키·IP 등록으로 격리 가능. 무료 한도는 1대분이라 추가분은 과금 |
| C. Oracle Cloud Always Free (고정 IP 포함) | $0 (무료 한도 내) | 이전 논의에도 나왔던 대안. 용량 확보·계정 정책 리스크는 있다 |
| D. 로컬 PC 유지 | $0 | PC가 꺼지면 주문·위험관리가 멈춘다. 지시서 목표(클라우드 독립 실행)와 상충 |

권고: 전략 검증을 통과하기 전에는 **새 서버를 만들지 않는다.** 통과 후에는 C(무료) 또는 B를 선택하고, 주문 전용 앱키·IP를 분리 등록한다.
웹 UI는 GitHub Pages 정적 화면 + 별도 인증 서버(주문 서버가 제공하는 관리자 API)로 구성하며, 계좌·키·주문 제어는 프런트에 두지 않는다.
관리자 인증은 기존 Google 로그인 외에 서버 측 관리자 판정 + 중요 작업 재확인(재인증)을 추가한다.

## 7. 시장·종목 하락 추세 필터 (사용자 추가 정책, 2026-10-11)

정책: 시장(KOSPI) 하락·급락 시 신규 매수 기본 차단, 개별 종목 하락 추세도 기본 차단, 추세 전환 전략('하락추세선 첫돌파')은 검증 후 예외,
기존 보유분의 손절·청산 관리는 계속, 하락장 수익 전략은 별도 모의검증 후 활성화. 필터 기준은 백테스트로 결정한다.

`quant-autotrade/backtest/regime_filter_study.py` (신호일 정보만 사용). 시장 하락 = KOSPI 120일선 대비 −3% 미만, 급락 = 5일 −5% 이하 또는 20일 고점 대비 −10% 이하.
종목 하락 = 종가<60일선 & 20일선<60일선. F0 필터 없음 / F1 시장 필터 / F2 시장+종목 필터 / F3 하락·급락 구간만(대조군). 비용·슬리피지 반영, 청산 3종.

결과 요약(ATR 추적 청산, 전체 기간 평균 순수익):
- 아무 날 진입 기준선: F0 +0.12% → F1 +0.03% → F2 +0.28%. 시장 필터만으로는 개선이 없고, 종목 하락 추세 제외(F2)에서 개선.
- 하락·급락 구간(F3)이 일관되게 나쁘지 않다: 구름 돌파 +1.26%, 눌림목 +1.48%(표본 238, 160건) — 반등을 놓칠 수 있다는 우려가 데이터에서도 보인다. 표본이 작아 확정할 수 없다.
- '하락추세선 첫돌파'(shortTermMaBreakout): F0 +0.25% → F1 +0.34%, 하락 구간만 +0.02%(10일 보유는 −0.70%). 시장 하락기에는 오히려 성과가 낮다 → 예외 허용보다 시장 필터 적용이 지지된다.
- 검증 구간(2024-09~)은 상승장이라 필터 차이가 작고(구름 돌파 +1.34→+1.44%), 하락 구간 표본이 부족하다.
- 고정 손익(−5/+10)은 필터와 무관하게 대부분 마이너스.
- 근사 MDD는 겹침 무시 방식이라 전 조합이 −100%로 포화되어 비교에 쓸 수 없다. 필터 전후 MDD 비교는 일자별 포트폴리오 시뮬레이션(동시 보유·자금 배분 반영)을 만든 뒤에 가능하다.

결론: 필터가 순수익을 확실히 개선한다는 근거는 아직 없다(검증 구간 표본 부족, 일부는 오히려 악화). 종목 하락 추세 제외가 상대적으로 낫지만 어느 필터도 통과 기준(검증 구간 z-하한>0)을 만든 전략이 없어 매수 활성화 결론은 바뀌지 않는다.

## 8. 포트폴리오 기준 결과 (`quant-autotrade/backtest/portfolio_sim.py`, 2026-10-11)

시뮬레이터가 일별 계좌 평가금액·현금·보유 종목을 계산한다(기존 −100% 포화 MDD 오류 해결). 기간 2022-04-07~2026-10-08, 234종목, 생존편향 있음.
설정 A(지시서 초기안): 동시 5종목, 종목당 10%, 전체 투자 30%, 현금·중복 보유 반영. 설정 B(대조): 종목당 20%, 투자 100%.
비용: 왕복 0.4% + 청산 슬리피지 0.3% + 진입 슬리피지 0.2%(거래 수익률에 반영). 호가단위·1주 단위·현금 이자는 무시.
벤치마크(같은 기간): KOSPI +145.8%(연 22.2%, MDD −38.6%), KOSDAQ −3.8%(MDD −47.4%). 개발 구간(~2024-09) KOSPI −4.3%, 검증 구간 +155.5%.

**가장 높은 순수익 (필터 없음, 설정 A)**
| 전략 | 누적 | 연환산 | 최대 손실(MDD) | 거래 | PF | 개발/검증 구간 |
|---|---|---|---|---|---|---|
| 눌림목 + ATR 추적 청산 | +81.7% | +14.2% | **−9.4%** | 192 | 1.98 | +21.7% / +49.3% |
| 눌림목 + 10일 보유 | +41.6% | +8.1% | −10.4% | 277 | 1.42 | +19.8% / +18.2% |
| 이동평균 구름 돌파 + ATR 추적 | +15.5% | +3.3% | −15.1% | 204 | 1.19 | +0.9% / +14.5% |
| 무작위 진입(대조군) + ATR 추적 | −8.8% | −2.0% | −18.0% | 267 | 0.89 | −9.3% / +0.7% |
| 현행 규칙(−3% 손절, +5% 익절) 눌림목 | −38.4% | −10.6% | −39.2% | 620 | 0.68 | −20.3% / −22.7% |
설정 B(투자 100%)의 눌림목+ATR 추적은 +113.0%(연 18.3%), MDD −35.1%.

**해석 (한계 포함)**
- 가장 좋은 조합은 눌림목+ATR 추적이다. 같은 자금 제약의 무작위 대조군(−8.8%)을 크게 앞서고 개발·검증 구간 모두 플러스다.
  투자 비중이 평균 23%라 KOSPI 매수후보유(+145.8%)보다 수익은 낮고(−8.0%p/년), 손실폭(MDD −9.4% vs −38.6%)이 작다.
- 그러나 승자 선택 효과가 있다(4검색기×4청산×3필터×2설정 중 최상위). 눌림목 표본은 신호 879건·체결 192건으로 작고, 거래 단위 통계 기준(앞선 z-하한)으로는 유의하지 않았다. 개발/검증은 같은 기간을 나눈 것일 뿐 독립 검증이 아니다.
  → 실거래 근거로 쓰지 않는다. 연구 후보로 지정해 모의매매에서 앞으로의(out-of-sample) 성과를 쌓는다.
- 현행 규칙(−3% 손절 / +5% 이하 익절)은 모든 검색기에서 −32%~−59%로 자금을 크게 잃는다. 이 규칙으로 자동 손절·익절을 켜는 것은 권하지 않는다(현재 봇은 로그 전용).
- 지시서의 'ALL'(전체 검색기 합산)은 −19.8%(ATR 추적)로 개별 눌림목보다 나쁘다. 점수 척도가 검색기마다 달라 합산 우선순위가 부정확하고, 손실 검색기가 포함되기 때문이다.

**하락 추세 필터 (설정 A, ATR 추적 / 10일 보유 / 누적, MDD)**
- 눌림목 ATR 추적: 필터 없음 +81.7%(−9.4%) → 시장 필터 +60.7%(−17.6%) → 시장+종목 필터 +49.5%(−16.0%). 필터가 수익과 MDD를 모두 악화.
- 구름 돌파 ATR 추적: +15.5%(−15.1%) → +20.4%(−10.1%) → +10.0%(−9.2%). 시장 필터는 개선, 종목 필터 추가는 수익 감소.
- 눌림목 10일 보유: +41.6%(−10.4%) → +12.0%(−18.6%) → +58.1%(−12.8%). 필터에 따라 부호가 엇갈림.
- 단기이평(shortTermMaBreakout): 필터 없음 −17.8%(−21.4%) → 시장 필터 +0.6%(−17.0%). 이 검색기만 필터 효과가 일관되게 보임.
→ 검증된 일관된 우위가 없으므로 하락 필터는 **연구용으로만 유지**하고 신규 매수 차단 규칙으로 확정하지 않는다.

## 9. 후보 생성 구조 (`quant-autotrade/research/candidate_gen.py`, 테스트 8건 통과)

- 스케줄 실측: 일일 스캔 20:10 시작·**저장 시각은 23:58 KST까지 밀림**(2026-10-08 응답 scannedAt 14:58 UTC). 21:00 batch_scan.py는 공매도·대차·재무 캐시 작업이고 패턴 결과를 만들지 않는다. 따라서 21:00 고정 조회는 어긋난다.
- 출처: 공개 읽기 전용 `GET /pattern-scan`(응답은 `{success, updatedAt, data}` 래퍼). 서버·스캔 스케줄·산식은 변경하지 않는다.
- 확정 판정: ①항목 마지막 봉 날짜가 한 값으로 모이고 scannedAt이 그날 20:10 이후 ②data_date 다음 평일 09:00 전에만 생성(주말·휴장 뒤 전일 데이터 재사용 차단) ③scanned가 최근 정상 회차 중앙값의 90% 이상(universe의 약 61%가 정상 - 일부 종목은 스캔 제외) ④같은 scannedAt이 3분 이상 변하지 않음.
- 스캔 실패 시 서버 캐시는 비워지지 않고 전일 값이 남는다 → 위 검사가 막고 사유를 `gen_log`에 기록한다.
- 후보는 (스캔일, 검색기, 종목)당 1회 생성·갱신 없음, 항상 `RESEARCH`·`live_eligible=0`. 진입(모의)은 다음 거래일만, 4일 지나면 만료. 갭 +2% 이상은 건너뜀.
- 모의 진입·청산은 백테스트와 같은 규칙(`exit_study.simulate`)으로 판정하고, 데이터 끝 봉의 시간 청산은 확정하지 않는다. 모의 성과는 백테스트·실거래와 합치지 않는다.
- 백테스트에 쓴 5개 중 '단기이평 돌파(shortTermMaBreakout)'는 `/pattern-scan` 응답에 없어 후보로 만들 수 없다(해당 결과는 백테스트에만 존재).
- 아직 안 한 것: 로컬 PC에서의 정기 실행(스케줄러)·키움 일봉 조회 연결·웹 UI 연동. 현재는 모듈과 테스트까지이며 실행하지 않았다.
