# 텔레그램 관제 (2026-10-11)

휴대폰 텔레그램으로 자동매매 시스템(로컬 봇 · 연구 엔진 · 모의매매)을 **읽기 전용**으로 관제한다. 주문·규칙 변경은 텔레그램으로 할 수 없다.
기존 종목 검색 산식, 모의 청산 전략, 수익률 계산, 로컬 봇의 −3%/+5% 규칙, `LIVE_SELL`(기본 꺼짐)은 바꾸지 않았다.

## 구조

```
 휴대폰 ◀──── api.telegram.org (HTTPS, 이 PC에서 나가는 요청만 · 들어오는 포트 없음) ────▶ 로컬 봇 프로세스(main.py)
                                                                       ├─ 손절·익절 판단 루프 (기존, 건드리지 않음)
                                                                       └─ 텔레그램 스레드 3개 (실패해도 위 루프에 영향 없음)
                                                                            ├ tg-sender  : 발송 대기열(telegram.db) 비우기, 재시도·백오프
                                                                            ├ tg-poll    : 롱 폴링으로 명령 수신 → 읽기 전용 응답
                                                                            └ tg-monitor : 15초마다 기록을 읽어 알림 적재 (autotrader.db · research.db · status.json 읽기 전용)
```

- 알림의 근거는 이미 남는 기록이다: `autotrader.db`(봇 이벤트·주문), `research/research.db`(후보·모의 거래·생성 로그), `research/status.json`(연구 작업 상태). 봇·연구 작업 코드를 호출하지 않는다.
- 후보 선정 이유(`reasons`)는 `candidates.reasons` 열에 저장된다(`candidate_gen.py`가 `ALTER TABLE ADD COLUMN`으로 자동 추가, 판정에는 쓰지 않음). 열이 없는 옛 DB는 이유 없이 표시한다.
- 새 코드: `tg_config`(설정·가림) · `tg_api`(Bot API) · `tg_store`(telegram.db) · `tg_notify`(대기열·발송·장애 상태) · `tg_data`(읽기 전용 조회) · `tg_format`(서식) · `tg_views`·`tg_commands`(명령 응답) · `tg_monitor`(감시) · `tg_service`(스레드·인가·시작 판정) · `telegram_setup`(페어링) · `procguard`(단일 실행).
  기존 코드 변경: `bot.py`(주문 오류 문구 상수 2개 + 읽기 전용 `health()`), `main.py`(단일 실행 잠금·감시 작업 옵션·텔레그램 시작), `server.py`(테스트용 `AUTOTRADER_PORT` 환경변수), `candidate_gen.py`(`reasons` 열), `restart.ps1`·`stop.ps1`.

## 처음 설정 (한 번)

봇 폴더 = 환경변수 `AUTOTRADER_DIR`, 없으면 `C:\Users\<사용자>\autotrader` (로컬 봇이 실행되는 곳).

1. (저장소에서) 최신 코드를 봇 폴더에 반영하고 자동 실행을 등록한다 — 관리자 권한 불필요:
   ```powershell
   powershell -ExecutionPolicy Bypass -File quant-autotrade\local_bot\install_bot.ps1
   ```
   바뀐 파일은 `backup_<시각>\`에 먼저 복사한다. `.env`·`.token`·DB·로그는 건드리지 않는다. 봇을 재시작한다.
2. 봇 폴더에서 **`telegram_setup.bat`** 을 실행한다.
   - BotFather 의 봇 토큰을 붙여 넣는다(입력은 화면에 보이지 않고 `.env`에만 저장된다).
   - 화면에 **일회용 코드**(8자리, 10분 유효, 5회 틀리면 중단)가 나온다. 휴대폰 텔레그램에서 그 봇에게 개인 메시지로 `/pair XXXX-XXXX` 를 보낸다(또는 화면의 링크를 열고 "시작").
   - 맞으면 `TELEGRAM_ALLOWED_USER_ID`·`TELEGRAM_CHAT_ID` 가 `.env`에 저장되고 봇이 다시 시작된다.
3. 텔레그램에 "자동매매 봇 시작" 알림이 오면 연결 완료. `/test` 로 확인한다.

| 항목 | 위치 / 이름 |
|---|---|
| 설정 파일 | `C:\Users\<사용자>\autotrader\.env` (GitHub에 올라가지 않음) |
| 설정값 이름 | `TELEGRAM_BOT_TOKEN` · `TELEGRAM_CHAT_ID` · `TELEGRAM_ALLOWED_USER_ID` |
| 발송 대기열·상태 DB | 봇 폴더 `telegram.db` |
| 로그 | 봇 폴더 `logs\autotrader-날짜.log` (토큰·긴 숫자열은 가려서 기록) |

토큰 폐기·교체: BotFather 에서 `/revoke` 후 `.env` 의 토큰을 지우고 `telegram_setup.bat` 을 다시 실행한다. 계정 변경은 `telegram_setup.bat --repair`.
설정 확인: `python telegram_setup.py --status` (값은 가려서 표시) · 실제 발송 테스트: `python telegram_setup.py --test`.

- **전송은 최소 1회**다. 요청이 텔레그램에 닿은 뒤 응답만 못 받은 경우(읽기 시간 초과)에는 재시도로 같은 알림이 한 번 더 갈 수 있다(텔레그램에 멱등키가 없음).
- 휴장일(평일)에는 스캔이 없어 "장 마감 스캔 미확정" 경고가 올 수 있다. 메시지에 "휴장일이면 정상"이라고 적는다.
- 백테스트 · 모의매매 · 실계좌 성과는 섞지 않는다. 메시지 머리에 🔎[연구] · 🧪[모의] · 🏦[실계좌] 를 붙이고 섹션을 분리한다.

## 보안

- 토큰·ID는 `.env` 에서만 읽는다. 로그와 오류 문구는 토큰 모양과 10자리 이상 숫자열(계좌번호 등)을 가린다. 주문번호는 끝 4자리만, 사용자 ID는 끝 3자리만 표시한다. 계좌번호는 어디에도 표시하지 않는다.
- **인가**: `TELEGRAM_ALLOWED_USER_ID` 와 개인 채팅(`chat.type=private`, 채팅 ID 일치)만 통과. 그룹·채널은 **무응답**(주인이 보내도), 다른 사용자는 "개인 전용" 안내(10분에 1회)만 받고 주인에게 "허용되지 않은 접근 시도" 경고가 온다.
- 처음 `/start` 를 누른 사람을 자동 등록하는 경로는 없다. 페어링은 **PC 콘솔에 표시되는 일회용 코드**로만 하며 봇 본체에는 등록 기능이 없다.
- `TELEGRAM_CHAT_ID` 가 음수(그룹·채널)이거나 허용 사용자 ID 와 다르면 시작하지 않는다.
- `TELEGRAM_API_BASE` 는 공식 주소 또는 `http://127.0.0.1` 만 인정한다(토큰이 엉뚱한 서버로 가지 않게).
- 오래 꺼져 있던 동안 쌓인 명령(10분 이상 지난 것)에는 답하지 않는다. 연타(10초에 16건 초과)는 무시한다.

## 자동 실행 · 복구

- `install_bot.ps1` 이 작업 스케줄러에 **`AutotraderBot`** 을 등록한다: 로그온 1분 뒤 + 지금부터 5분마다 `pythonw main.py --watchdog`. 현재 사용자 권한(관리자 불필요), 중복 실행 안 함.
  봇이 이미 살아 있으면(`bot.lock`) 새 프로세스는 조용히 끝나므로, 죽었거나 강제 종료된 경우에만 5분 안에 되살아난다. 잠금은 30초마다 갱신되며 죽은 PID·갱신이 끊긴 잠금은 즉시 인계한다.
- `stop.bat` 은 `NO_AUTOSTART` 표식을 남겨 감시 작업이 다시 켜지 않게 한다(`restart.bat`·`run.bat` 으로 시작하면 해제). `restart.bat` 은 `planned_stop.flag` 로 "계획된 재시작"임을 알려 비정상 종료 경고를 막는다.
- 시작할 때 이전 실행 상태(`telegram.db` run_state)와 PC 가동 시간으로 최초/계획된 재시작/부팅 후 시작/비정상 종료를 구분해 알린다. 15초마다 생존 신호를 기록한다.
- 제거: 작업 스케줄러에서 `AutotraderBot` 삭제 (`Unregister-ScheduledTask -TaskName AutotraderBot -Confirm:$false`).
- 연구 작업(`AutotraderResearch`)은 그대로다. `candidate_gen.py` 갱신 때문에 `install_bot.ps1` 이 `research_app` 의 해당 파일만 복사한다(작업 재등록 없음).

## 한계 (확인된 것과 아닌 것)

- **PC가 완전히 꺼지거나 인터넷이 끊기면 텔레그램으로는 알릴 수 없다.** 켜진 뒤 "비정상 종료 후 복구/부팅 후 시작"과 지연 전달로 사후에 알린다.
- 체결 여부는 증권사 체결 조회 API가 아니라 **잔고 변화**로만 판단한다(체결 조회 필드가 이 저장소에서 검증되지 않았다). 체결가·손익은 알림에 넣지 않는다. 부분 체결은 수량 감소로만 보인다.
- 매도 주문(`kt10001`)·잔고(`kt00018`) 실호출은 여전히 미검증이다(`LIVE_SELL` 꺼짐 유지).
- 실제 텔레그램 서버와의 통신은 가짜 HTTP 서버로만 시험했다. 사용자 PC에서의 실사용 테스트 절차는 아래.
- `research_job.py` 의 `pid_alive` 는 Windows에서 종료된 프로세스의 핸들이 열려 있으면 "살아 있음"으로 오판할 수 있다(봇 쪽 `procguard.py`는 수정함). 연구 작업 잠금은 20시간 안에 인계되므로 영향은 작지만 별도 정리 대상이다.

## PC 전체 꺼짐 감시 — 검토안 (구현·VM 변경 없음, 승인 필요)

| 안 | 내용 | 비고 |
|---|---|---|
| A. PC → VM 하트비트 | PC가 5분마다 `https://goodbyestar.cloud` 에 서명된 핑을 보내고, VM(FastAPI 스레드)이 밤·장중에 15분 넘게 핑이 없으면 **같은 텔레그램 봇**으로 알림 | VM 코드·배포 변경 필요 → 승인 후. 외부 포트는 열지 않음(PC는 나가는 요청만) |
| B. 외부 하트비트 서비스 | healthchecks 류에 PC가 핑, 끊기면 서비스가 텔레그램으로 알림 | 외부 계정 필요, VM 변경 없음 |
| C. 현행 유지 | 켜진 뒤 사후 알림만 | 추가 작업 없음 |

권장: A (이미 있는 VM·도메인 재사용, e2-micro 부하는 5분 1요청 수준). VM 운영 변경이므로 승인 전에는 하지 않는다.
