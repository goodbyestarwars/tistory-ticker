# 지지 방어·거래량 재폭발·전일 고가 돌파 단타 — 장중 그림자 기록 (2026-11-26)

연구 전용 관측 기록이다. 주문·자동매매·검색기 화면·공개 API와 연결하지 않는다. 결과가 좋아도 실계좌 반영은 별도의 구체적 승인과 아래 사전 판정 기준 충족이 전제다.

## 왜 기록하나

- 사용자가 11-26 보고 판단한 패턴: 112·224일선/수평 박스 하단의 지지를 지키며 시장이 밀려도 덜 밀리다가, 거래량이 붙으면서 전일 고가를 돌파해 슈팅이 나오는 종목(한국화장품제조·로킷헬스케어·루닛).
- 일봉만으로 같은 조건을 5년 백테스트한 결과(`scripts/research/daytrade_support_breakout_study.py`, 2,516종목, 신호 2,988건): 당일 종가 평균 −1.54%, 익일 종가 −1.86%(왕복 0.4% 차감). 고가까지는 평균 +5.2% 가지만 종가에서 반납했다. 익절·손절을 걸어도 낙관 경계 +0.25%, 비관 경계 −2.6%로 결론 불가.
- 사용자가 실제로 보는 신호(체결강도, 호가 공백, 5분 단위 거래량·가격 흐름)는 일봉에 없고 서버에 과거 분봉·체결강도 이력도 없다. 그래서 **같은 조건의 종목을 장 시작 전에 확정하고 장중 값을 쌓아** 몇 주 뒤 같은 기준으로 검증한다.

## 사전 후보(장 시작 전 정보만)

직전 거래일 일봉이 `daily_prices`에 들어와 있어야 만든다. 직전 거래일 일봉이 있는 종목이 전체의 60% 미만이면 그날 후보를 만들지 않고(`stale_daily`) 5분 뒤 다시 시도한다. ETF 목록 조회 실패(50개 미만)도 `no_universe`로 보류한다. 오래된 일봉으로 후보를 만들지 않는다.

| 조건 | 내용 |
|---|---|
| SUP | 최근 10봉 최저가가 112일선 또는 224일선의 −5%~+6% 안(이탈 후 복귀 포함) |
| HOLD | 최근 5봉 최저가 ≥ 그 앞 20봉(t−25~t−6) 최저가 |
| SURGE | t−60~t−2 사이 일간 상승률 +15% 이상이 한 번 이상 |
| VOLX | 어제 거래량 ≥ 직전 5일 평균의 2배 |
| LIQ | 20일 평균 거래대금 ≥ 20억 |

- 기록 대상: LIQ 통과 + 4개 중 3개 이상, 최대 120종목(4/4 먼저, 같은 통과 수 안에서는 거래대금 순). 3/4는 조건 하나를 뺀 **비교군**이다.
- 보통주만(코드 끝자리 0), ETF·ETN 목록·스팩 제외. 판정식은 연구 스크립트와 같고 `ResearchParityTest`가 120개 무작위 계열에서 신호일마다 일치를 확인한다.
- 임계값은 백테스트에서 정한 출발점이며 이 기록으로 사후에 바꾸지 않는다.

## 장중 기록

- 09:00~15:30 5분 슬롯마다 **한 번**. 후보 전체의 네이버 polling 배치(40종목/요청, 기존 `market_temp_data`가 쓰는 같은 엔드포인트)에서 현재가·시가·고가·저가·누적 거래량·누적 거래대금·전일 기준가를 저장한다(2026-11-26 실응답으로 필드 `nv/ov/hv/lv/sv/aq/aa` 확인).
- **armed**(4/4 후보 중 현재가가 전일 고가의 98.5% 이상이거나 일중 고가가 전일 고가를 넘은 종목) 최대 20종목만 KIS로 체결강도(`FHKST01010300` `tday_rltv`)와 10호가 잔량 합·매도1/10호가를 추가 조회한다(종목당 2요청, 요청 간 0.12초). 슬롯당 최대 40요청이다.
- 값이 없으면 NULL이다. 0이나 직전 값으로 채우지 않는다. `base_ok=0`은 일봉 기준가와 공급자 전일 기준가가 달라(권리락 등) 전일 고가 기준이 틀릴 수 있다는 표시다.
- 놓친 슬롯(재시작·실패)은 복원하지 않는다. `observed_ts`는 실제 관측 시각이다.
- 한계: 5분에 한 번의 스냅샷이다. 슬롯 안의 체결 순서·정확한 돌파 시각·그 사이 체결강도는 알 수 없고, 일중 고가/저가는 공급자가 그 시각까지 보고한 값이다. 체결강도는 KRX 기준 단일 값이며 NXT 통합이 아니다.

## 표

- `sbs_day(trading_date, state, examined, fresh, candidates, note)`: 그날 후보 생성 결과(`ready`/`stale_daily`/`no_universe`).
- `sbs_candidate`: 후보와 판정 근거(이평·저점·급등률·거래량 평균·4개 플래그·`n_pass`)와 사후 `daily_json`(D0~D3 일봉).
- `sbs_obs(trading_date, slot, code)`: 슬롯 관측값.

돌파 사건 예(VM에서 읽기 전용):

```sql
SELECT o.trading_date, o.code, MIN(o.slot) AS first_slot
FROM sbs_obs o JOIN sbs_candidate c USING (trading_date, code)
WHERE o.day_high > c.prev_high GROUP BY 1, 2;
```

## 사전 판정 기준(결과를 보기 전에 고정)

- 관측 단위: 4/4 후보일 중 일중 고가가 전일 고가를 넘은 날(돌파 사건). 비교군은 같은 정의의 3/4 돌파 사건과 전체 후보의 일률.
- 진입 두 가지를 함께 보고한다: ① 연구와 같은 `max(시가, 전일 고가)` ② 첫 돌파 슬롯의 관측 현재가(더 보수적). 왕복 비용 0.4% 차감.
- 청산: 당일 종가·익일 시가·익일 종가, 그리고 슬롯 관측가 기준 +3%/−3%.
- 장중 확인 신호 분할은 **두 가지만** 사전 지정: ⓐ 첫 돌파 슬롯의 체결강도 ≥ 120 대 미만 ⓑ 매도 10호가 잔량 합이 당일 누적 거래량의 중앙값 비율 미만(호가 공백) 대 이상. 사후에 분할을 늘려 찾지 않는다.
- 결론을 내리는 최소 표본: 4/4 돌파 사건 60건 이상. 그 전에는 숫자만 보고하고 결론을 내리지 않는다(대략 몇 주~수개월 소요 추정, 일평균 돌파 건수에 따라 달라지며 미측정).
- 합격선: 비용 차감 후 평균 > 0이면서 비교군·분할 대조보다 우위, 해당 사건 중 단일 상위 사건을 빼도 유지. 미달이면 기록을 접거나 조건을 새 버전으로 만든다(과거 기록에 소급 적용하지 않는다).
- 통과해도 자동매매 반영은 사용자의 별도 승인이 필요하다.

## 운영·롤백

- 첫 기록은 배포 뒤 다음 거래일 장중부터다. 배포 시각이 장중이면 그날은 중간부터 기록되고 이전 슬롯은 비어 있다.
- 확인: `sqlite3 support_breakout_shadow.db "SELECT * FROM sbs_day ORDER BY trading_date DESC LIMIT 3; SELECT slot, COUNT(*) FROM sbs_obs WHERE trading_date=date('now','+9 hours') GROUP BY slot;"`, 로그 `support_breakout_shadow`.
- 끄기: `volume_surge_live.py`의 호출 두 줄 삭제(DB·기록은 그대로 남는다).
- 외부 호출량: 네이버 배치 슬롯당 최대 3요청, KIS 슬롯당 최대 40요청(armed가 없으면 0). 기존 호출 간격·예산 정책을 유지하며 새 키·계정은 없다.
