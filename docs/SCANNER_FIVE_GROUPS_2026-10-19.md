# 검색기 5개 통합 · DART 재무 필터 (2026-10-19)

## 메뉴와 보존 경계

| 분류 | 메뉴 | 원래 판정/태그 |
|---|---|---|
| 단타 | 실시간 거래량·수급 | 9Pay A/B + 장중 거래량 급증(초기 급증·실시간 매집 의심·기존 매집봉 재상승) |
| 단타 | 추세 돌파 | 하락추세선 돌파 / 이평 기울기 전환 |
| 스윙 | 바닥 형성 | 저점상승 / 쌍바닥 / 역헤드앤숄더 / 박스권 하단 |
| 스윙 | 눌림·재돌파 | 이평 눌림 / 첫 눌림 재돌파 / 급락 후 첫 눌림 4단계 |
| 중장기 | 224일선·구름대 + 재무 | 기존 maCloudBreakout 기술식 + 새 longTermQuality 재무 관문 |

기존 13개 검색기의 수는 12개 패턴 키(숨길 openingGap 포함)와 실시간 9Pay A/B를 합한 것이다. 기존 TABS 설명, 개별 detect 함수, 기존 API 패턴 버킷, scan_hits/pattern_tracks 네임스페이스를 보존한다. 갭상승 버튼만 만들지 않는다. 원래 12개 패턴 키는 API에서 계속 조회할 수 있다. 기술 판정/품질 함수 11개는 작업 전 AST와 동일하다.

같은 종목은 메뉴당 한 줄로 합치며 members에는 원래 항목/패턴/단계가 남는다. 같은 유형·같은 단계만 중복 제거하고 서로 다른 단계/패턴은 보존한다. A/B 감시 항목과 신호 기록 모두 포함한다. 실시간 가격이 있으면 수신 가격과 시각을 우선하며 일봉 가격을 현재가로 바꾸지 않는다. 거래량 30초/9Pay 10초 폴링과 기존 공유 API를 재사용한다. 장외·구버전·API 오류·결측을 표시한다.

## 이력·성과

통합 메뉴용 합산 승률을 만들지 않는다. 메뉴 아래 원래 검색기 선택에서 해당 scanner ID의 이력·성과·성공/실패를 조회한다. 장기 기술식의 이전 기록은 maCloudBreakout 선택으로 계속 볼 수 있다. 재무 통과 후보는 별도 pattern:longTermQuality에 정규 daily_scan부터 기록한다. 과거 기술식 성과를 재무 필터 성과로 재사용하지 않는다. SQLite-only rescan은 기존처럼 포착 이력을 다시 만들지 않는다. 장기 관문 이력은 새로운 정규 스캔부터 쌓인다.

## 재무/유동성 관문

`pattern_detect.LONG_TERM_FILTER`에서 주가 5,000원, 시총 3,000억원, 최근 20봉 평균 거래대금 30억원, 재무 확인 유효기간 7일을 조정할 수 있다. 거래대금은 기존 OHLCV의 종가×거래량 대용값이며 화면에 밝힌다. 연속 20봉이 없거나 시총을 확인하지 못하면 제외한다. 연간 영업이익·순이익 모두 >0 필수, 최신 단독분기는 두 이익 중 하나라도 <0이면 제외한다. 값이 없거나 무한대/NaN이면 제외한다.

기존 fundamentals_cache.json의 data[code].annual/latest_quarter/dividend를 유지하고 screening 증거를 추가한다. 기존 재무자료만 있는 구버전 캐시는 통과시키지 않는다. 재무 수집은 기존 batch_scan의 20분 예산·커서·DART 키를 재사용하며 현재 장기 기술 후보를 먼저 확인한다. 새 타이머나 주문 프로세스는 만들지 않는다. --long-term-only는 기존 캐시에서 현재 장기 후보만 갱신하는 배포/수동 점검 옵션이며 전체 이어달리기 커서를 변경하지 않는다.

### 최신 공시와 단독분기

- 공식 DART list 정기보고서 목록에서 가장 최근 회계기간의 접수번호를 찾고, 최신 정정본을 확인한다. 최신 접수번호와 재무 API의 접수번호가 다르면 반영 대기로 제외한다. 과거의 흑자 보고서로 폴백하지 않는다.
- 공식 fnlttSinglAcntAll의 IS/CIS thstrm_amount는 분/반기 보고서에서 **3개월 금액**이다. thstrm_add_amount는 누적값이다. Q1/Q2/Q3 단독분기는 전자, Q4는 같은 CFS/OFS 기준의 연간값 - Q3 누적값을 사용한다. Q3 누적이나 기준이 없으면 Q4를 만들지 않는다.
- 연결(CFS) 우선/별도(OFS) 폴백은 기존과 같으며 어느 기준으로 수집했는지 보존한다. Q4 차감은 서로 다른 기준을 섞지 않는다.
- 연간은 제출기한 전에는 전전년, 4월 1일 이후에는 전년 자료 이상을 요구한다. 최신 기간은 4/1 연간, 5/16 1분기, 8/15 2분기, 11/15 3분기부터 요구한다. 12월 결산의 보수적 기준이며 비12월 결산 등 기간이 맞지 않는 자료는 확인 불가로 제외한다. 조기 제출한 새 기간도 공시 목록에서 확인한다.
- 확인 시각이 새로워도 보고기간이 오래됐으면 제외한다. 접수일 누락/미래 날짜도 제외한다. 확인 7일 초과 또는 기간 변경은 API 응답 시점에도 재검사하므로 오래된 일일 캐시가 계속 통과하지 않는다.
- 최신 공시는 정기 사업/반기/분기보고서 기준이다. 잠정실적·자율공시의 비표준 수치를 정기보고서 대신 쓰지 않는다. 조회와 다음 갱신 사이의 새 공시는 갱신 전까지 반영 지연이 있을 수 있다.

ROE·부채비율·영업이익/순이익 YoY와 최신 단독분기 이익·공시일·확인일을 표시한다. ROE 등 부가 비율 누락은 미확인으로 표시하며 흑자 관문을 대신하는 값으로 쓰지 않는다. 재무 흑자/이 조건은 재무적으로 무위험하거나 상승한다는 뜻이 아니다.

공식 금액 정의: [DART 단일회사 전체 재무제표](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020).

## API 및 제외 집계

/pattern-scan의 기존 patterns 키를 유지하며 patterns.longTermQuality와 longTermFilter를 추가한다. 후자는 기술 후보/통과/제외 종목 수, 조건값, 사유별 건수, 제외 종목과 사유를 제공한다. 한 종목에 여러 제외 사유가 있으면 사유 합계는 제외 종목 수보다 클 수 있다. 기존 기술식 버킷을 필터로 덮어쓰지 않는다.

## 모양 우선 공통 표시·정렬 (2026-11-05)

사용자 선택: 단타·스윙·중장기 전체 검색기에 공통 적용. `auto-wave.shapeOf` 한 함수를 공통 차트와 검색기에서 재사용한다. 기존 5개 메뉴·원래 탐지 결과와 이력·확정/관찰/연구/제외/만료 상태·집계를 보존하고, 동일 상태 안에서 기존 후보의 최근 20일 종가 모양을 우선 정렬한다. 저점 상승·고점 하락·상승 뒤 눌림/반등·변동폭 축소를 설명한다. 점수는 모양 정렬용 내부 척도이며 승률·주문 우선순위가 아니다.

새 전종목 탐지나 원래 수치 관문의 완화는 포함하지 않는다. 특히 A/B 실주문·일봉 신호 검증·재무 관문을 모양으로 승격하지 않는다. 현재 응답의 miniChart/closes_20d를 재사용해 추가 종목별 API 호출이 없으며, OHLC/거래량이 아닌 종가 요약임을 화면에 표시한다. 모양 자료 부족·모듈 로딩/실패를 구분한다. 기존 자료를 복사해 보조 필드를 붙이며 원본을 변경하지 않는다.

검증: 신규 test_chart_scanner_shape.js(가격 단위 불변·한 봉 급등 저항·조정/반등·결측/역순·정렬·상태/집계/원본 보존), 기존 public_states/groups/loading·차트/추세/파동/인과성 회귀 통과. 실제 검색기 JS/CSS와 합성 응답의 5개 메뉴×1440/390px 10개 조합에서 모양 라벨·가로 넘침 없음·브라우저 오류0·주문 요청0 확인. 운영 성과/수익성 검증과 구분한다.


## 후보 선정도 모양 우선으로 전환 (2026-11-05)

이 절은 앞선 ‘기존 후보 정렬만 변경’ 범위를 대체한다. 웹 기본 5개 메뉴는 **전체 저장 일봉에서 새로 선정**한 `shapeSelection.groups`를 사용한다. 기존 숫자 검색으로 걸린 종목만 재정렬하지 않는다. 원래 `patterns`·`pullbackScan`·scan_hits·추적 기록·signalReview·A/B 주문 피드는 그대로 보존하고, 이전 결과는 개별 검색기 기록에서 확인한다. 새 후보는 모두 관찰이며 확정/주문으로 승격하지 않는다.

공통 `auto-wave.selectShapesOf`를 브라우저/서버에서 재사용한다. 서버의 기존 Python 배치가 종목별 DB 입력을 임시 NDJSON 파일로 순차 작성하고 Node worker 1회(300초 상한)가 같은 JS를 실행한다. 신규 상시 프로세스·타이머·시장 API 호출은 없다(기존 KRX 공개 정적 지도 1회 재사용). 24/40/80/160/224봉은 관찰 규모이지 패턴이 반드시 그 기간에 완성돼야 한다는 관문이 아니다.

- 거래량·가격 회복: 가격 지지 뒤 거래량 재확장·종가 회복. 일봉이며 기존 실시간 A/B와 구분한다.
- 추세 돌파: 실제 고점 연결 저항 또는 관찰 구간 고점 저항을 종가로 회복.
- 바닥 형성: 선행 하락 뒤 반복 저점 지지, 저점 상승 또는 봉 변동폭 축소.
- 눌림·재돌파: 선행 상승 뒤 저점 유지, 조정 거래량/변동폭 둔화, 반등 맥락. 고점 대비 고정 5~15%·고정 2~8봉·이평 거리로 배제하지 않는다.
- 중장기: 장기 지지·응축·저항 회복의 모양을 먼저 찾고 기존 DART 연간/단독분기/시효 관문을 적용한다.

보통주·거래정지/ETF/동전주 제외와 기존 시총 3,000억원·20일 평균 거래대금 30억원 관문은 별도로 유지한다. OHLCV 결측/역순/중복/오류·최신 완료 거래일 불일치는 제외한다. 저점 붕괴·반복 대량 음봉은 눌림/바닥으로 만들지 않는다. 모양 점수는 내부 표시 순위일 뿐 성과·주문 신호가 아니다. 그룹당 공개 최대60개는 응답/메모리 상한이며 종목 순서가 아닌 형태 점수로 정렬한다. 장기 재무 관문은 후보 상한 적용 전에 검사하고 API에서도 시효를 재확인한다.

`daily_scan`과 DB-only `rescan_patterns`의 기존 완료 경로에서 새 선정만 갱신한다. 이전 캐시가 계산 중 바뀌면 쓰지 않는다. 새 필드는 루트 `shapeSelection` 하나만 원자 갱신하며 기존 결과/이력을 덮어쓰지 않는다. 오류/미완료/구버전이면 웹은 스캔 대기를 표시하고 이전 수치 후보로 가장하지 않는다. 재계산 실행 시 최신 완료 거래일을 검증하며, 공개 응답의 데이터 기준일 불일치·36시간 초과·미래 계산 시각도 노출하지 않는다.
