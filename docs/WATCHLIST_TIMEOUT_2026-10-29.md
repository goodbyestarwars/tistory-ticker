# 관심종목 조회 timeout 회복 — 2026-10-29

사용자 사진의 서버 응답 지연/관심종목을 불러오지 못했습니다 안내는 조회 timeout 경로다. 이 문구만으로 로그인 실패나 목록 삭제를 뜻하지 않는다. 사이트 전체 점검에서 간헐적인 API·loopback 지연과 자원 대기를 확인했다. [진단](SITE_PERFORMANCE_2026-10-29.md).

watchlist.js에서 인증상태/목록의 credentials:include, cache:no-store GET만 timeout일 때750ms 뒤 한 번 재시도한다. 각8초 한도는 유지해 최악 대기는 약16.75초이며 무한반복하지 않는다. 401·403·HTTP오류·형식오류는 재시도하지 않는다. 저장 PUT·주문 API·로그인 OAuth·보안 설정은 변경하지 않는다. 동시 refresh는 기존 loadInFlight를 공유한다. 성공 전 빈목록 저장을 하지 않으며 기존 목록 보존과401 로그아웃 처리를 유지한다.

최초 로딩 실패 때 동일 문구를 위아래로 중복하지 않고 목록 안 오류만 표시한다. 이미 불러온 목록에 실패하면 상단 안내를 유지한다. 다시 불러오기 버튼은 기존 공통 ui-btn/ui-btn-secondary를 사용한다.

오프라인7개 회귀+그룹삭제 기존회귀 통과: 인증/목록 일시timeout 자동회복, 지속timeout2회상한,401무재시도,목록 보존,미인증/만료,중복refresh,오류중복제거,개인 GET옵션과쓰기없음. VM/서비스 재시작·DB/목록/계정 설정 변경 없음. 서버 경합 자체를 해결한 것이 아니라 일시 지연 후 수동 클릭 없이 회복하는 프런트 완화다.
