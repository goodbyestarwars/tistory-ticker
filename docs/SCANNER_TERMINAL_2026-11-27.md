# 검색기 터미널 개편 (2026-11-27)

사용자 지시 "9Pay 검색기 메뉴 및 UI 전면 개편"의 구현 명세. **화면·정보 구조만 바꾼다.** 검색 알고리즘, 실계좌 매매 로직, 매수·매도 조건, 주문 허용 설정, 운영 서비스는 변경하지 않는다.

## 구성

| 파일 | 역할 |
|---|---|
| `js/pattern-scan.js` | 기존 검색 엔진·API·이력. `#pattern-scan[data-terminal]`일 때만 상세를 오른쪽 칸에 두고 `nine-scanner-select/list/quotes` 이벤트와 `PatternScan.terminal`(rows·live·quote·refreshQuotes·state)을 내보낸다. 속성이 없으면 기존 동작 그대로 |
| `js/scanner-terminal.js` | 터미널 레이아웃·사전/장중 탭·상태 구분·호가 연결·자동매매 검색기 보기 (읽기 전용, 주문·쓰기 호출 없음) |
| `css/scanner-terminal.css` | Soft UI 토큰(라이트)·`--dk-*`(다크), 새 `!important` 없음, 860px 이하 한 칸씩 |
| `data/scanner-validation.js` | 6개 전략의 매수·매도 조건과 검증 결과(고정 연구값, 2026-11-27 기준). 없는 값은 `null`(화면 '미집계') |
| `js/skin-main.js` | `/page/pattern-scan`에서 위 세 파일을 지연 로드(`skin.html` 수정 없음) |
| `js/skin-menu.js` | 종목 메뉴: `일반검색기`(`/page/pattern-scan`) · `자동매매 검색기`(`/page/pattern-scan?view=auto`). 기존 직접 URL 보존, 접근 키는 같은 `scanner`(관리자) |

재사용: `OrderBook.init/select`(호가·최근 체결), `NineAPI.data(... {private:true})`(`/autotrader/status`), 공통 `chart-core` 경로의 기존 상세 차트(pattern-scan `openDetail`).

## 일반검색기

- 위: `일반검색기 | 자동매매 검색기`, `사전 스캔 | 장중 스캔`, 기존 단타·스윙·중장기 탭과 개별 검색기 버튼(6개 분류 그대로).
- PC 3열 30% · 25% · 45%: 목록 / 호가·최근 체결 / 차트·포착 근거. 종목을 누르면 페이지 이동 없이 세 칸이 동시에 바뀐다. 860px 이하는 `목록·호가·차트` 한 칸씩.
- 목록 카드: 포착 시각, 데이터 기준일, 선정 이유(기존 카드 줄), 현재 상태 칩.
- **장중 판정 지원 범위**: 기존 엔진에서 장중 재판정이 있는 것은 `거래량·가격 회복`(9Pay A/B + 장중 거래량 급증 감시)뿐이다. 이 탭만 `장중 신규 포착 / 장중 조건 충족 / 조건 이탈 / 신호 대기`로 구분하고 30초마다 시세를 갱신한다. 나머지 5개는 장중 스캔에서 "장중 스캔 미지원 검색기"로 안내하고 실시간 검색으로 표시하지 않는다. 사전 스캔 목록에서는 현재가가 무효화 가격 아래인지만 `가격 이탈/가격 유지`(엔진 재판정 아님)로 보여 준다. 시세 2분 초과분은 이탈 판정에 쓰지 않는다.

## 자동매매 검색기

- 총 6 · 채택 1 · 검증 중 5. `채택 전략 / 승격 대기 전략 / 전략별 검증 성과` 세 탭.
- 전략마다 **채택 상태 · 서비스 실행 상태 · 실계좌 주문 허용 상태**를 별개 칸으로 표시한다. 서비스 실행은 일봉 스캔 수신·9Pay 감시, 주문 허용은 `/autotrader/status`의 `flags`(수신 못 하면 '미수신', 스윙 신규 매수 스위치는 상태 API에 없어 '미확인').
- 성과는 백테스트 / 일봉 모의(서버 포착 추적, 런타임에 `/pattern-scan` 모니터로 채움) / 장중 모의 / 실계좌를 **서로 섞지 않고** 따로 표시. 표본 수·평균 수익률·승률·PF·MDD, 값이 없으면 `미집계`.
- 승격 판단: 요건(끝난 매매 100건·PF 1.3·1건 평균 +1.0%, exit-v2)을 넘어도 "사용자 승인 전에는 켜지 않음"으로만 표시한다. 승격·주문 기능은 화면에 없다.

## 운영 엔진 정책 확인 (읽기 전용, 2026-11-27)

Google VM(`instance-20260712-153038`) 배포 코드의 `live_engine.py`: `SWING_ENTRIES = False`, `NINEPAY_ENTRIES = False`. 신규 매수는 주도주 조용한 눌림(사용자가 자동매매 화면에서 켜는 `flags.leaderPullback`)만 가능한 구조로, 요청한 채택 정책과 일치한다. 주도주 칸의 실제 켜짐 여부는 운영 시점 값이라 이 화면이 `/autotrader/status`로 그때그때 보여 준다. 스윙 신규 매수 스위치는 상태 API에 노출되지 않는다(별도 변경 항목이 필요하면 사용자 지시 후).

## 알려진 한계

- 승률·MDD는 5개 메뉴 백테스트 자료에 없어 `미집계`.
- 전략별 실계좌 체결·손익은 장부 집계가 없어 전부 `미집계`.
- 장중 모의는 거래량 급증 신호 30거래일 한 구간만 있다(9Pay A/B 장중 모의는 신호 100건 누적 전).
- 호가·최근 체결은 관리자 원천 시세 경계 안에서만 동작한다(서버가 판정, 메뉴 숨김만으로 보호하지 않음).
