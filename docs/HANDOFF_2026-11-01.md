- 실제 주문·매수·매도·정정·취소·계좌·브로커 로그인/모드 전환은 차단 유지. 연구 권한을 실거래 승인으로 해석하지 않는다.
- 키/계좌/쿠키/개인키/IP/환경 파일 값을 Git·문서·응답에 쓰지 않는다. 게이트웨이는 로그인 비밀키를 복사하지 않고 기존 인증 API에 쿠키를 전달해 검사한다. KIS upstream에는 쿠키/Authorization을 넘기지 않는다.
- Docker/Lean은 사용자가 **Oracle에서만 승인**했다. PC Docker 재설치/이미지 다운로드 금지. Oracle Lean은 네트워크 차단 및 자원 제한 유지.
- 확인 완료: gateway 단위 9개, 기존 관리자 메뉴 Python 3개, 메뉴 1280/900/390px에서 소유자 인접 배치·Google 단독 방문자 숨김, 실제 UI 1280/390px 검색·화면 전환, 종목 검색/상태, 캐시 전략 실행 및 Lean 백테스트.
- 허용 계정 통합 테스트는 별도 프로세스 인증 fixture였다. 실제 사용자의 Google 로그인 세션으로 검증했다고 주장하지 않는다. 운영 익명 접근 403은 확인했다.
- 메뉴 테스트: `node test/test_kis_menu.js`(Playwright/Edge 필요), 기존 회귀 `python test/test_autotrader_menu_end.py`. Python 3.14에서는 `python -m unittest test.test_autotrader_menu_end`가 표준 test 패키지와 충돌했으므로 파일 직접 실행.

## PC 정리 및 현재 접근 제약

- 사용자는 이전 후 PC 데이터 삭제를 승인했다. 이 세션의 삭제 실행은 도구 정책에 차단되어 수행하지 못했다. 이후 현재 확인에서 **`C:\KIS-Lab`이 존재하지 않는다.** 누가 어떤 범위까지 정리했는지는 이 세션에서 확인하지 못했으므로 전체 삭제 완료라고 단정하지 않는다.
- 따라서 이전 문서의 `C:\KIS-Lab` 작업 경로/가상환경을 그대로 실행하면 실패한다. 새 작업은 현재 저장소 위치와 실제 런타임부터 확인한다.
- **인계 작성 시 SSH alias `9pay`는 지정 개인키 파일 부재로 인증 실패했다.** 서버를 새로 점검한 것이 아니다. 새 키 생성/자격증명 변경을 임의로 하지 말고, 기존 키의 안전한 위치 또는 승인된 접근 방법부터 확인한다.
- KIS Code Assistant MCP는 공식 API·예제 코드 검색용이다. 실계좌 연결과 별개. 이 대화에서 검색 응답 확인 완료. PC 소스 `C:\Users\goodb\.mcp-servers\open-trading-api\MCP\KIS Code Assistant MCP\server.py`는 인계 작성 시 존재 확인했다. Claude 연결은 작업지시서를 전달했을 뿐, 완료 여부는 확인하지 않았다.
- Claude MCP 설정 시 기존 설정 백업/중복 방지 후 공식 README에 따라 `uv --directory <폴더> run server.py --stdio` 사용. Docker·증권 자격증명 불필요. 삭제 도구 차단을 다른 실행 경로로 우회하지 않는다.

현재 새 기능 구현 요청은 없다. 다음 사용자 지시 범위에서 기존 공통 모듈을 재사용하고 관련 검증 후 반영한다. 다른 세션에 인계할 때는 이 문서와 상세 README 링크로 간결하게 전달한다.
