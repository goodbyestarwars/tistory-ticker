## 데이터·시간·이력 계약

- 기존 `title/start/link/source/market/status`와 응답 `success/data/source/cached`는 유지한다. 추가 `calendarHealth`는 선택 필드다.
- 공통 필드: `eventId`, `symbol`, `company`, `eventType`, `fiscalPeriod`, `eventDate`, `scheduledAt`, `timezone`, `kstDate`, `sourceUrl`, `verification`, `verifiedAt`, `reportedAt`, `sources`, `history`.
- 알려진 분기는 국가·정규 심볼·회계분기·행사 종류로 식별한다. 날짜가 바뀌어도 ID는 유지한다. 서로 다른 IR 행사 종류는 같은 실적 카드로 억지 병합하지 않는다.
- 공시 예고는 `announced/disclosure`와 `dateBasis=disclosure_receipt`다. 접수일을 발표 예정일로 꾸미지 않는다. 예정일을 본문에서 확인하면 별도 예정 이벤트가 만들어진다.
- 상태: scheduled/reported/changed/cancelled. 사라졌다는 이유로 완료·취소하지 않는다. 다른 출처가 날짜에 이견을 보이면 기존 날짜와 양쪽 근거를 유지하고 `verification=conflict`로 표시한다. 같은 공식 문서의 변경 또는 명시적 정정 공시는 날짜 변경 이력을 남긴다.
- 발표 이후에도 예정일·콜 시각·원문과 변경 이력을 유지한다. 수집 오류는 정상 빈 응답과 별도 상태이며 마지막 이벤트를 지우지 않는다.
- 정확한 시각은 UTC offset이 있는 값만 변환한다(서머타임 포함). Finnhub AMC는 한국 다음날, BMO는 같은 날 표시다. DMH는 한국 당일/다음날이 모두 가능하므로 **한국 날짜 미확정**을 표시하고 미국 현지일에 둔다. 세션만 있는 자료에 정각 시각을 만들지 않는다.

## 선택적 첨부 분석

기본 수집은 공개 본문만 사용하며 첨부 성공에 의존하지 않는다. `calendar_attachment.py`는 이미 정당하게 확보한 **로컬 파일만** 받는 오프라인 도구다. URL 다운로드 기능이 없다. PDF 텍스트/표 배치는 pypdf가 있을 때 최대10페이지, HWPX는 제한된 ZIP/XML 텍스트, HWP는 설치된 hwp5txt가 있을 때만 지원한다. 이미지·스캔 PDF는 수동 추출/검증 필요로 반환한다. OCR 날짜를 자동 확정하지 않는다.

파일5MB·해제20MB·텍스트80,000자·부모12초(최대15초)·Linux 작업자192MB/CPU8초 상한. API 핸들러에서 실행하거나 새 패키지를 운영에 자동 설치하지 않는다. IRGO 첨부에는 재사용 허가를 별도로 확보해야 한다.

- input, form submit(Enter/버튼), compositionstart/end, 검색 취소를 지원한다. 앞뒤 공백·대소문자를 정리하고 다중 단어는 AND다. 월 이동 뒤에도 검색어가 유지된다.

- 기존 날짜 달력과 국내/미국을 유지하고 경제 필터를 추가했다. 날짜 목록/월 결과는 처음8건과 나머지 펼치기를 제공하며 모든 이벤트는 DOM에 남긴다. 긴 제목·모바일 줄바꿈·정확한 콜 시각·상태·출처·확인 시각·24시간 경과 안내를 표시한다.
- NineHttp, EarningsCalendarFeed, 기존 전역 디자인·간격·다크 토큰을 재사용한다. 공유 feed의 `.month()` 배열 반환은 그대로이고 `.status()`만 추가했다.

## 갱신·자원·배포 승인 경계

새 상시 프로세스/스레드/수집 서비스 없이 기존 `daily-scan-warmer`에 캘린더 갱신 호출을 연결했다. 스캔 판정·신호·주문·손익·계좌 코드 변경은 없다. 월별 갱신30분, 공식 IR6시간, 구성7일, 오류 재시도도 같은 공급자 예산 안에서 수행한다. API는 디스크에서 로드된 마지막 이벤트만 읽고 최대6개 월 갱신 요청을 큐에 넣는다. 연도 조회도 저장 이력만 읽어 외부12개월 fan-out을 막는다. API 캐시60초, 원본 캐시10분, 공급자별 정상/오류 상태는 별도 원자 파일에 보존한다.

이 워머는 같은 스레드에서 순차 실행하므로 외부 지연 때 기존 응답 예열 주기가 늘어날 수 있다. 실제 e2-micro RSS 메모리·CPU·일봉 워머 지연·DART 전체 커버리지는 운영 배포 승인 후 측정해야 한다. 완료/무부하로 가정하지 않는다.
