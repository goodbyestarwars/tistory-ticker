# 주요 지수 거래량 영속 캐시 — 2026-10-24

## 경로와 보존

`stock-search.js` → 기존 `/domestic-market-indicators/chart?market=KOSPI|KOSDAQ&interval=day&long=1` → `domestic_market_indicators.fetch_chart` → `index_daily_history.get`.

기존 단기 일봉·주봉·분봉 경로는 그대로다. long=1 일봉은 HTTP 요청에서 KIS를 기다리지 않는다. VM 앱 폴더의 `index_daily_history_KOSPI.json` / `index_daily_history_KOSDAQ.json`을 읽고 필요한 수집만 백그라운드로 예약한다. 파일은 git 제외·배포 복사/재시작 대상 밖의 런타임 자료이며 지우지 않는다. 임시 파일에 쓰고 fsync+원자 교체한다. 지수별 최대900봉, 초기 요청은1100일·최대20쪽. OHLCV/date/source=kis/collectedAt/confirmed를 보존한다.

최초 백필 이후에는 미확정 봉의 가장 이른 날짜, 또는 최종 확정 봉 다음 날부터만 조회한다. 오늘 봉은 미확정이며 다음 날짜에 다시 확인한 봉만 확정한다. KIS가 짧은 조회에도 오래된50봉/연속조회 헤더를 주면 요청 시작일에 도달한 첫 페이지에서 중단하고, 범위 밖 과거 봉은 덮어쓰지 않는다. 거래량 결측 행은 제외하고 실제0은 보존한다. ETF 거래량·거래대금·미국 지수 대체 자료는 사용하지 않는다. 단위는 `unverified`.

앱 시작 시 가벼운 워머가60초마다 두 파일을 확인한다. 기존 `market_clock` 활성 구간에는60초, 장외에는6시간이 지나야 실제 증분 수집을 예약한다. 단일 워커와 지수별 진행 작업 공유로 외부 조회 중복과 동시 백필 부하를 막는다. 실패 재시도는60초이며 마지막 성공 파일과 시각을 보존한다. 기존 앱 프로세스 안의 스레드만 사용하며 별도 서비스/VM/타이머/DB는 추가하지 않는다.

## 응답과 프런트

기존 source/rows/errors에 `cache` 추가:

- `asOf`, `lastSuccessAt`, `lastAttemptAt`, `lastErrorAt`, `lastError`
- `backfillComplete`, `refreshing`, `stale`, `usingLastValid`, `state`, `volumeUnit`, `retryAfterMs`

빈 캐시도 즉시200으로 반환하며 `refreshing=true`면 프런트가2초 간격으로 거래량 응답만 확인한다. 가격 요청을 반복하거나 가격 차트를 기다리게 하지 않는다. 백필 완료 후 자동 반영. 정상 조회60초, 실패60초 재시도. 숨김/다른 지수로 전환하면 재시도 중단.

프런트 상태는 KOSPI/KOSDAQ별 map/meta/job/next를 독립 보존하고 같은 지수의 Promise를 공유한다. A→B→A 전환에서도 요청을 시작한 화면 세대 ID가 다르면 화면에 반영하지 않는다. 도착한 map은 정확한 날짜로 합치며 거래량0도 덮어쓴다.

공통 `chart-core.addVolumePane`에 `updateData/destroy`를 추가했다. 지수의 거래량 도착은 캔들 차트를 제거하지 않고 거래량 패널만 추가·갱신한다. 먼저 켠 RSI가 있으면 거래량 패널을 앞에 삽입한다. 범위·그리기·가격 툴팁·가격 시리즈는 유지하고 거래량 평균/배수/의존 매물대·흔적만 갱신한다. 미확정 원단위와 공급 기준일·마지막 성공 수집 시각, 지연/실패 상태를 화면에 표시한다.
