# 장중 선택 종목의 1시간 방향 판단

목표는 사용자가 장중에 직접 확인한 시점의 매수 기준가 대비 +3%, 손절 −3%, 이후 60분이다. 현재는 학습·교차검증된 예측기가 아니라 `hour-rules-v1` 실험 조건 필터다. 승률·목표 도달 확률·기대수익은 계산된 값이 없어 `probability: null`로 유지한다.

## 사용과 기준 가격

검색·호가 화면에서 사용자가 종목을 직접 클릭하거나 종목을 검색해 선택하면 **1시간 방향 : 상승가능 / 하락가능 / 판단 어려움** 중 하나와 바로 아래 짧은 근거를 표시한다. 순위 목록·급등 제외 설정·변수 표는 이 화면에서 제거했다. URL로 자동 진입한 경우에는 계산하지 않고 확인 전의 `판단 어려움`을 표시한다. 밑줄 텍스트 버튼은 제거했고, ↻ 아이콘(접근성 이름 `다시 확인`)은 새 수동 입력을 만든다. 자동 알림·신호 폴링·저장 결과 복원은 없다. 결과는 60분이 지나면 로컬에서 만료 표시만 하며 API를 호출하지 않는다.

새 `hour-direction-rules-v4`은 학습하지 않은 **양방향 규칙 가설**이다. `validated:false`, `probability:null`을 반환하며 도움말에 실험 판단·확률/수익 우위 미검증을 명시한다. 기존 후보 통과/탈락을 상승/하락으로 바꾸지 않는다. 기존 후보 API는 호환을 위해 유지한다.

선택 방향 확인 가능 시간은 국내 거래일 09:05 이상 14:30 미만이다. KRX 정규장 15:30 마감까지 60분을 확보하는 범위다. 14:30 이후에는 1시간이 남지 않았다는 짧은 이유와 판단 어려움을 반환한다. 기존 후보 API의 09:05~09:15 제한은 호환을 위해 유지한다. 그 밖에는 현재 확인할 수 없다는 `판단 어려움`만 반환하며 공급자 조회를 하지 않는다. 확인 시점 KRX 최우선 매도호가 1주를 기준가로 쓰고 +3% 목표·−3% 손절을 호가단위로 올림한다. 실제 주문 체결가는 아니며 비용·슬리피지·순수익 +3% 달성 여부는 검증되지 않았다. 각 종목의 `checkedAt`과 `expiresAt=checkedAt+60분`을 고정한다.

## 방향 판단

두 방향 모두 당일 연속 완결 분봉·실제 체결강도·최신 호가·전일 확정 거래량이 필요하다. 누락·미래/10초 초과 시세·넓은 스프레드·정지·도달 불가능한 목표·이미 급등/분봉 점프는 보류한다. 거래량이 0이어서 VWAP와 잔량 부담을 계산하지 못하는 경우도 자료 부족이다. 최종 응답 직전 신선도를 재확인한다.

v3는 최근 **5개 완결 분봉의 시작 가격**과 최근 최대 30분 VWAP 근사에 가격 방향이 모두 맞아야 한다. 상승은 최근 종가가 5봉 시작 가격보다 높고 VWAP 이상이며 현재 체결가가 종가보다 0.2% 초과 밀리지 않아야 한다. 이에 저점 상승 패턴 **또는** 체결강도 105 이상이 확인되어야 한다. 하락은 반대 가격 조건과 고점 하락 패턴 **또는** 체결강도 95 이하를 요구한다. 저점 상승과 고점 하락 패턴이 함께 나타나면 보류한다. 이미 1분봉에서 1.5% 이상 급락한 구간도 보류한다.

거래량 가속 1.3배·최근 2분/전일 전체 1%는 방향의 필수 문턱에서 제거했다. 미달이어도 위 가격·확인 근거가 맞으면 방향을 표시하고 `거래량은 약해`를 덧붙인다. 목표 방향의 보이는 잔량/최근 거래량 비율도 보류 조건에서 보조 근거로 바꿨다. 거래량이 약하지 않은 경우 비율 1배 초과를 `앞쪽 잔량은 부담돼`로 표시한다. 벽이나 거래량만으로 방향을 만들지 않는다. 보이는 10단계 밖 잔량·취소·+3% 도달 시간은 알 수 없다. +3%/−3%·60분 기준과 미검증 상태는 유지하며, 방향 표시가 +3% 도달 확률이나 양의 기대손익을 뜻하지 않는다.

### +3%/−3% 목표 움직임 점검 (v4)

v3가 작은 반등을 +3% 목적의 상승가능으로 표시하던 의미 불일치를 바로잡는다. 방향 조건을 통과해도, 직전 최대10개 완결 분봉 종가의 로그가격 회귀 기울기와 분당 로그수익률 표본 표준편차로 목표 움직임 민감도를 별도로 점검한다. 상승 기준은 `max(0,기울기×60)+표준편차×sqrt(60)`가 `log(실제 호가단위 목표가/직전 완결 종가)` 이상일 때만 통과한다. 하락도 반대 기울기와 `log(직전 종가/손절 기준가)`로 대칭 점검한다. 매도1호가 기준·호가단위 때문에 실제 필요한 이동폭이 3%보다 커질 수 있다.

이는 최근 속도/변동성이 60분 동안 유지된다는 **미검증 민감도 가정**이다. 한 표준편차는 예측 상한·도달 확률·신뢰구간이 아니며, 회귀와 제곱근 시간 확대를 실제 미래 분포로 검증하지 않았다. 통과는 목표 움직임 조건을 충족하는 규칙 가설일 뿐이다. 불통과 상승은 `작은 반등은 있지만 1시간 +3% 움직임 근거가 부족해`, 하락은 대칭 이유로 보류한다. 상세 budget/required move·표본수·기울기·noise와 movementBudgetValidated:false는 기존 회전 기록에만 보존한다. UI·공개 스키마·호출 수·VM 작업 제한·확률null은 유지한다.

2026-10-07 같은 저장 입력12회 재계산: v3 상승1/하락4/보류7 → v4 상승0/하락1/보류11. NAVER09:48은 상승으로 바뀌었던 사례이나, 미검증 움직임 계산 약0.40%가 실제 목표까지 약3.09%보다 작아 보류된다. 미래 결과를 사용한 성공률 검증은 아니다. 상승 샘플이 없으면 없는 것으로 보고한다. 작은 반등/횡보·실제 tick 목표/기준가 갭·미래 입력 배제·양방향·기존 요청 경계 관련96건 회귀 통과.

## 기존 후보 API 규칙 (선택 방향 v3와 별도)

| 변수 | 기본 조건 / 계산 |
|---|---|
| 저점 상승 | 최근 3개 완결 1분봉 저가의 엄격 상승 또는 양옆 완결 봉으로 확인한 두 피벗 저점의 상승 |
| 가격 흐름 | 최근 완결 종가 > 개장 가격, 종가 ≥ HLC3를 거래량으로 가중한 분봉 VWAP 근사, 현재 체결가가 직전 종가보다 0.2% 초과 밀리지 않음 |
| 거래량 가속 | 최근 2분 거래량 / 앞선 2분 거래량 ≥ 1.3배 |
| 전일 대비 | 최근 2분 거래량 / 직전 거래일 KRX 전체 거래량 ≥ 1% |
| 체결강도 | KIS 실제 당일 체결강도 `tday_rltv` ≥ 110% |
| 호가 간격 | (최우선 매도 − 최우선 매수) / 최우선 매도 ≤ 0.3% |
| 매도 잔량 부담 | 목표가 아래 **보이는** 매도 잔량 / 최근 2분 거래량 ≤ 1배. 호가 10단계 밖 잔량은 알 수 없음 |
| 급등 제외 | 확인까지의 최대 고가·최우선 매도호가가 시가 대비 +5% 이상이면 제외 |
| 한 번의 점프 제외 | 완결 1분봉 고가/시가 상승 또는 다음 봉 시가/직전 종가 갭이 +1.5% 이상이면 제외 |
| 거래 제한 | 일시 정지·상한가보다 높은 목표가 제외. 정지 여부·상한가 누락은 자료 부족 |

문턱은 내부 고정 가설이며 선택 종목 화면에서 설정을 요구하지 않는다. 기존 후보 API의 설정은 호환을 위해 남긴다. 직전 최대 5봉 최고가 돌파와 매수·매도 잔량벽은 관찰값을 제공한다. 총 매수 잔량이 많다는 이유만으로 상승이라고 판정하지 않고, 스냅샷으로 취소와 체결을 구분하거나 벽 소진 시간을 예측하지 않는다.

저점 상승 자체의 한국 주식 60분 +3% 확률이 검증된 것은 아니다. 기술적 패턴에 추가 정보가 있을 수 있다는 연구도 시장·시간축이 다르므로 이 문턱의 승률로 옮길 수 없다. [Lo·Mamaysky·Wang 원문](https://www.nber.org/papers/w7613). 호가 불균형 연구도 다음 한 틱을 분석하므로 1시간 목표에 곧바로 적용하지 않는다. [Gould·Bonart 원문](https://arxiv.org/abs/1512.03492).

## 데이터와 실패 처리

새 필터는 모든 가격·분봉·호가·체결강도·전일 거래량을 KIS 시장 구분 `J`(KRX)로 맞춘다. 기존 화면의 KRX/NXT 통합 호가 또는 키움 수정 분봉을 새로운 필터 입력으로 재사용하지 않는다. 공식 계약: [분봉](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_time_dailychartprice/inquire_time_dailychartprice.py), [체결](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_ccnl/chk_inquire_ccnl.py), [호가](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_asking_price_exp_ccn/chk_inquire_asking_price_exp_ccn.py), [순위](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/volume_rank/volume_rank.py).

선택 방향은 확인 직전 **최대 30분**의 연속 완결 봉만 계산한다. 09:05에는 09:00~09:04의 5봉이고, 13:00에는 12:30~12:59의 30봉이다. 방향의 시작 가격은 최근 5봉, VWAP 근사는 최근 최대 30분이며 개장 이후 전체 VWAP가 아니다. 이전 구간의 패턴을 새 방향 근거로 재사용하지 않는다. 기존 후보 API는 09:00부터 확인 직전 분까지를 유지한다. 현재·미래 봉은 가격·거래량을 읽지 않으며, 누락 봉을 메우지 않는다. 분봉을 요청하고 수신하는 동안 분이 바뀌면 부분봉이 완결됐다고 가정하지 않고 자료 부족으로 돌린다. 공급자 호가 접수시각·체결시각이 각각 10초 이내여야 하며, 전체 조회 완료시에도 후보의 신선도를 다시 확인한다. 공통 `envelope.updatedAt`으로 신선도를 판단하지 않는다.

순위 확인은 KIS 거래량·거래증가율·거래대금 순위 각 최대 30개를 중복 제거하고, 거래대금순 최대 24개만 상세 확인한다. **전 종목 검사가 아니다.** 제외 마스크는 투자위험·관리/정리·우선주·거래정지·ETF/ETN·SPAC 등을 제거한다. 응답은 풀 수·상세 평가 수·건너뛴 수·실패 순위 항목을 구분하고 `fullMarket: false`를 제공한다. 순위 밖 종목은 선택 종목 확인으로 점검한다.

확인된 제외 조건은 `rejected`, 필요한 자료 누락은 `insufficient_data`, 모든 조건 통과만 `candidate`다. 자료 부족·상세 조회 상한은 조건 미달로 바꾸지 않는다. 조회가 실패했거나 검사 범위가 일부이면 전체 시장에 후보가 없다는 문장을 출력하지 않는다.

## 운영 API와 자원

새 선택 종목 화면은 공개 `GET /hour-direction?code=035420&name=NAVER`를 호출한다. 반환은 `code,name,direction,label,reason,checkedAt,expiresAt,horizonMinutes,targetPct,stopPct,entryPrice,targetPrice,stopPrice,probability:null,validated:false,rulesVersion,sourceStatus,recorded`이며 상세 변수는 로컬 기록에만 둔다. 기존 공개 `GET /hour-candidates?mode=ranked` 또는 `mode=selected&code=035420&name=NAVER`. `max_open_rise_pct=5`, `max_minute_jump_pct=1.5`로 두 문턱을 전달한다. CORS는 기존 사이트 정책을 따른다. 응답은 `Cache-Control: no-store`, IP당 분당 3회, 프로세스 전체 동시 확인 1개, 상세 조회 워커 3개다. 새 상시 프로세스·폴러·유료 서비스·DB 테이블은 없다.

작업 예산은 30초, 개별 시세 HTTP 읽기 제한은 4초다. 시세 함수 호출 시작을 기능 전체에서 0.1초 간격(초당 최대 10회)으로 제한해 워커의 공급자 요청 집중을 막는다. 기존 토큰 발급·만료 재시도·잠금 대기는 이 제한보다 길 수 있으므로 30초 HTTP 응답을 보장하지 않는다. 화면은 45초에 중단하고, 서버의 진행 중 HTTP가 끝날 때까지 전역 확인 잠금을 유지한다. 바쁜 경우 409, 공급자 확보 실패는 원문을 노출하지 않고 503이다.

전일 확정 거래량만 당일 메모리에 캐시한다. 당일 입력·결과는 VM `hour_candidate_checks.jsonl`에 수동 확인 때만 기록하며, 5MB를 넘으면 `.1`로 회전한다. 주소·인증정보·주문정보는 기록하지 않는다. 기록 실패는 `recorded: false`이며 필터 계산과 구분한다.

## VM 부하 제한

새 상시 수집기·프로세스·타이머·자동 조회는 없다. 선택 방향은 1종목·작업 스레드 1개, 두 수동 API를 합쳐 프로세스 전체 동시 작업 1개를 유지한다. 진행 중인 작업이 있으면 큐에 쌓거나 공급자를 추가 호출하지 않고 409를 반환한다. IP당 분당 3회와 기존 KIS 호출 시작 간격 0.1초도 유지한다. KIS 일별분봉은 한 번에 최대 120건을 제공하며 그중 최근 30분만 계산하므로 오후 확인을 위해 페이지를 추가 조회하지 않는다. 정상 시세 조회는 전일 거래량 첫 확인을 포함해 5회, 전일 값이 캐시되면 4회로 기존과 동일하다(기존 토큰 발급·재시도는 별도). 확인 기록도 기존 5MB 두 파일 회전을 공유한다.

로컬 Windows/Python에서 120봉 입력·30봉 계산을 1,000회 측정한 평균은 2.27ms, 단일 계산 Python 할당 최고치는 약 20KB였다. VM 실측 또는 전체 HTTP 응답·프로세스 메모리 수치가 아니며, 네트워크 I/O는 기존과 동일하게 작업 상한으로 제한한다. 공식 [KIS 분봉 계약](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_time_dailychartprice/inquire_time_dailychartprice.py), [KRX 정규장 시간](https://regulation.krx.co.kr/contents/RGL/03/03010100/RGL03010100T1.jsp).
