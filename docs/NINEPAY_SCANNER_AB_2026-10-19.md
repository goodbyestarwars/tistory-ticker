## 운영 불일치와 수정 기준

기존 #756 관찰기는 최근 3분에 전일 거래량의 3% 증가 → 1% 눌림 → 고점 재돌파였다. 이번 A/B 조건과 다르다. `kiwoom_9pay_observer.py`의 같은 관찰기를 `ab70-v1`로 교체하며, 기존 `volume_surge_live.py`의 3% 검색은 02번 기존 검색기로 유지한다. UI는 `ruleVersion=ab70-v1`이 아닌 운영 신호를 새 A/B 결과로 표시하지 않는다.

공통 필수 조건은 수신 시각 기준 09:00:00~09:29:59에 전일 확정 거래일 전체 거래량 대비 70% 이상 유입 관측이다. 80%도 같은 시간 안에서 관측되어야 우선 평가한다. 09:30:00 이후 처음 확인한 값은 당일 제외하며 과거 시각을 추정하지 않는다. 09:30 이전 충족 종목은 순위에서 이탈해도 구독에 고정하고 오후에도 감시한다. 최대 20개 제한과 순위권 밖 종목 누락은 남는다.

공유 통합 피드에 장전 물량이 포함되는지 실측되지 않았다. 따라서 **소스별 최초 09시 이후 수신 누적값을 빼서 관측 이후 유입 하한**을 계산한다. 하한이 70% 이상일 때만 통과한다. 정확한 09:00 누적값을 0으로 만들지 않으며 늦게 발견한 종목은 실제로 충족했더라도 놓칠 수 있다. UI 비율의 `≥`와 ‘최초 관측’은 이 의미다. WS/KIS 소스가 바뀌거나 누적값이 감소하면 별도 기준값을 만들고, 해당 리셋 표본으로 신호를 내지 않는다.

전일 기준은 기존 `daily_prices`에서 휴장 달력상 정확한 직전 거래일 행만 사용한다. 더 오래된 행을 전일로 대체하지 않는다. B의 저점 상승은 **직전 확정 일봉 2개**의 저점 비교다. 당일 미완성 봉이나 미래 봉은 사용하지 않는다.

| 분기 | 진입 판정 |
|---|---|
| A | 70% 충족 후 관측 고점에서 처음 1% 이상 눌림 → 그 고점을 초과하고 같은 소스 누적 거래량도 직전 표본보다 증가 |
| B | 직전 확정 일봉 저점 2개 상승 + 수신 시가가 전일 종가보다 높음 → 첫 1% 눌림 저점이 시가 이상에서 지지 → 저점 대비 0.3% 이상, 직전 관측가보다 상승. 고점 재돌파 불필요 |

눌림 1%와 반등 0.3%는 이번 구현의 명시적 관측 기준이며 수익성이 검증된 값이 아니다. 반등이 시작된 뒤 첫 눌림 저점을 다시 이탈하면 그날 재시도하지 않는다. B 시가/확정 봉 결측은 B만 미확인이며 A를 막지 않는다. A와 B가 동시에 발생해도 `YYYY-MM-DD:종목코드`로 한 신호만 내보낸다. 실제 매수·매도 판단이나 자금 우선순위는 이 모듈에 없다.

## API·저장·부하

기존 `GET /health/realtime`의 `data.ninePayResearch`에 `ruleVersion`, `items`, `orderStatus`, `persistenceError`, `queueDropped`를 추가한다. `items`는 후보 기본정보와 최근 관측을 합친 복사본이다. 초기 순위 가격은 `rankPrice`이며 체결을 아직 받지 못한 현재가를 만들지 않는다.

표시 필드는 `code/name`, `price/changeRate`, `volumeRatio/first70At/first80At/priority80`, `gapPct/risingLows/lows/lowDates`, `pullbackLow/peak/bSupportBroken/entryInvalid`, `stage/branches/signalAt/signalPrice`, `at/sampleAt/source/volumeMissing/excluded`다. `previousDay`는 거래량 기준일이다. `at`는 서버 수신 시각, `sampleAt`는 폴백 관측 시각이다. 거래소 원천 전송 지연은 확인하지 못하므로 화면에서 수신 후 경과와 구별한다. 결측은 null이며 UI는 미수신·미확인으로 표시한다.

키움 공식 [주식체결 0B 예제](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/blob/main/examples/국내주식/실시간시세/subscribe_domestic_stock_trade_pubsub.py)의 FID 13은 누적 거래량, 16은 시가다. 기존 파서가 16을 `openPrice`로 전달하도록 추가한다. 실제 필드 값·통합시장 시가의 의미·등록 한도는 장중 실측 전이다. KIS 기존 메모리 순위 폴백에 시가가 없으면 새 호출로 보충하지 않는다.

키움 순위 2건/60초·공유 WebSocket 1개·후보 최대 20개와 기존 KIS 메모리 표본을 재사용한다. 브라우저는 상태 스냅샷만 10초마다 읽으므로 접속자마다 키움 호출/구독이 늘지 않는다. 숨겨진 탭은 폴링하지 않고 중복 요청을 막는다. 전일 데이터는 기존 SQLite 읽기이며 새 외부 조회·타이머·프로세스가 없다.

`kiwoom_9pay_state.json`은 날짜·버전별 최초 충족 증거·단계·신호를 원자적으로 저장하는 작은 런타임 파일(최대 20 추적)이다. 70%·80%·단계 전환과 주기 점검 때 저장하고, 저장 실패 시 신규 신호 발행을 보류한다. 같은 날 재시작 시 저장된 증거만 복원하며, 다른 날짜·다른 버전·확인할 수 없는 과거 시각은 재사용하지 않는다. 기존 제한 JSONL에 후보·신호·표본 MFE/MAE·90초 초과 관측 공백 수/최대 간격을 기록한다. 계좌·키·토큰·주문 정보는 저장하지 않는다.
