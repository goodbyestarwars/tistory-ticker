# 9Pay 장중 실계좌 연결

## 2026-10-22 다음 거래일 누락 카운터 이월 수정 (코드 반영, 현장 미검증)

9Pay 연구 관찰기의 `queueDropped`는 주문을 보호하는 중요한 당일 누락 증거다. 종전 서버 구현에서 `_run`의 구독 객체는 자정에도 살아 있고 `Subscription.dropped_events`가 프로세스 기간 전체에 누적되어, **전날 발생한 이벤트 누락이 다음 거래일까지 매수 차단으로 이월**될 수 있었다. 오늘 첫 루프에 `queueDropped=0`을 강제 설정하는 단순 해제는 같은 날 재시작의 누락 증거까지 잃으므로 금지했다.

수정: 한국시간 날짜 전환 시에만 과거 일자의 누락 합계를 버리고 현재 일자와 일치하는 상태 파일만 복원한다. 구독 누적 건수의 **당일 시작 기준값**을 기록한 뒤 새로 늘어난 누락분만 합산한다. 같은 날 재시작하면 저장한 당일 누락값을 그대로 복원한다. 새 누락이 1건이라도 생기면 PC의 기존 `queueDropped` 차단이 작동한다. 관련 회귀 시험: `test/test_kiwoom_9pay_queue.py`의 전일 473건/다음날 0건, 다음날 신규 누락 1건, 같은 날 3건 복원. `rankError`·`amountFallback`·`persistenceError`, 10초 신호·120초 순위 만료, STOP·승인·예산·매도는 변경하지 않는다.

이 변경은 **코드 준비 및 GitHub 반영 기록**으로서 지금 VM에 적용되거나 오늘 매수가 복구됐다는 근거가 아니다. 평일 08:00~20:00 VM 자동 배포 보류 보호정책 유지, 수동 VM 재시작/주문 금지. 배포 후 `GET /health/9pay`에서 거래일별 `queueDropped`와 장중 피드·순위 시각을 별도 실측해야 한다. 전날의 누락을 소급 신호나 소급 주문으로 재구성하지 않는다.
