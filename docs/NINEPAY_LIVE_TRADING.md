# 9Pay 장중 실계좌 연결

## 현재 상태 (2026-10-19 07:18 KST)

사용자가 "켜"라고 명시 승인해 PC `NINEPAY_LIVE_TRADING`을 활성화했다. 기존 08:55 예약 실행을 유지하며, 장중 유효 신호와 기존 승인·예산·STOP·미확정 주문 점검을 통과하면 자동 주문할 수 있다. 다른 설정은 변경하지 않았다. 주문 함수를 차단한 읽기 점검으로 활성화와 승인·미체결/장부·공유 여력을 확인했다. 장중 수신·실체결은 아직 검증하지 않았으며, 아래 설치 당시의 비활성 기록과 구분한다.

- 사용자 선택: 기존 PC 엔진의 100만 원 예산, 최대 3종목, 종목당 30만 원, 10만 원 현금 유보를 공유한다. 매도는 기존 엔진의 -3% 연속 확인, -5% 즉시 손절, +3% 도달 후 고점 대비 -2.5% 규칙을 사용한다.
- VM의 기존 관찰기는 주문 기능이 없다. `/health/realtime`의 `ninePayResearch`에 신호 ID·발생가를 추가하고, PC가 HTTPS로 3초마다 확인한다. REST 순위가 불완전하거나 120초 이상 지났거나, 신호가 10초 이상 지났거나, 거래량이 결측이면 매수하지 않는다.
- PC 전용 파일은 `quant-autotrade/local_bot/live_runner_9pay.py`, `ninepay_signal_client.py`, `ninepay_trade.py`, `live_engine.py`다. 기존 엔진 소스를 저장소에서 검토 가능하게 관리하고, `trade_once`에 매도 점검/매수 분리 옵션만 추가했다(기본값은 기존 동작). PC `live_kiwoom.py`와 기존 장부를 공유하며 별도 계좌·주문 프로세스를 만들지 않는다.
- 순서: 30초마다 기존 매도 점검 → 3초마다 신규 단타 신호 → 해당 30초 주기의 기존 검색기 매수. 기존 매수 단계는 매도를 재평가하지 않아 연속 확인 횟수가 두 번 증가하지 않는다. 이미 유효한 단타 신호가 우선하며, 미래 신호를 위해 예산을 별도 예약하거나 기존 보유를 강제 청산하지 않는다. 9Pay가 켜진 동안 피드 불완전/장외/저장 오류이면 기존 신규 매수도 보류하되 매도 점검은 먼저 수행한다.
- 수신·주문 직전 모두 `ab70-v1`, A OR B 근거, 거래량 결측 없음, 당일 09:00~09:29:59의 실제 최초 70% 관측, 10초 이내 신호를 확인한다. 09:30 최초 충족·구버전·저장 실패·대기열 누락은 통과시키지 않는다. 주문 직전 STOP·승인·스위치·미확정 장부를 다시 확인한다.
- 실제 주문에는 기존 `LIVE_TRADING=1`·계좌 지문 승인 파일과 별도로 PC `.env`의 `NINEPAY_LIVE_TRADING=1`이 필요하다. 07:18 사용자 승인으로 활성화했다. 키·토큰·계좌번호는 문서/저장소에 넣지 않는다.
- 설치 시 실행 중인 작업을 멈춘 뒤 PC `live_runner.py`·`live_engine.py`·수신/주문 어댑터를 함께 백업하고 동일 커밋의 네 파일을 함께 반영해야 한다. `live_runner_9pay.py`는 PC에서 `live_runner.py` 이름으로 설치한다. 이전 엔진과 새 runner를 섞으면 분리 옵션 호출에서 오류로 중단되므로 일부 파일만 교체하지 않는다. `.env`·승인 파일·제외 목록·장부는 복사/수정하지 않는다. 기존 주문 클라이언트 `live_kiwoom.py`를 유지한다. 롤백은 스위치를 끄고 작업 중지 후 네 파일을 함께 복원한다.
- 매수 전 계좌·기존 보유/미체결·장부의 미확정 주문·제외 종목·가용 현금·전체 예산·종목 수를 다시 확인한다. 키움 `ka10001` 현재가가 신호가보다 0.3% 넘게 높으면 추격하지 않는다. 주문 전 intent를 먼저 저장하고 응답이 불확실하면 자동 재시도하지 않는다.
- 미확인: 장중 실시간 0B FID 13 값, 20개 등록 성공/누락, REST 순위 정확성·지연, KIS 폴백 시 신호 수·시점, 실제 체결·MFE/MAE·손익, PC에서 실주문 응답. 첫 장중 관측과 소액 실행 전까지 9Pay 스위치를 켜지 않는다. 이전 PC 시작 현금 점검은 `WAIT`이었으며 실제 활성화 전 잔고·미체결·자금·승인을 다시 조회해야 한다.

## 2026-10-19 수정 적용 범위

사용자는 수정 후 master 반영을 승인했다. 이번 변경은 master에 코드/테스트/문서를 반영하며 PC 운영 파일·예약 작업·스위치는 수정하지 않는다. master push만으로 PC 코드는 설치되지 않는다. VM A/B 관찰기는 최신 master의 구현을 그대로 사용하며 VM 재배포나 20:10 스캔 변경이 없다. 웹 주문·체결·손익 표시는 계속 미연동이다. 최대 3종목·종목당 30만원·10만원 유보는 기존 선택을 유지했으며, 총 100만원을 초과하는 별도 예산을 만들지 않았다.
