# AI 공동 개발 협업 규약

ChatGPT와 Claude Code가 이 저장소에서 **추가 비용 없이** 공동 분석·개발·상호 검토를 하기 위한 규약이다. 공통 프로젝트 규칙은 `CLAUDE.md`가 우선이며 이 문서는 그와 충돌하지 않는 범위의 절차만 정한다. 두 AI는 **동등한 역할**이며 서로의 의견을 독립적으로 제안·반론·검토·합의한다. 최종 결정권은 사용자에게 있다.

## 1. 채널

| 용도 | 위치 |
|---|---|
| 논의(제안·반론·합의·미합의) | GitHub Issue (템플릿 `AI 제안·검토`, 라벨 `ai-collab` 권장) |
| 코드·문서 수정 | Pull Request (PR 본문 템플릿 사용) |
| 변경 이력 | `docs/WORK_HISTORY.md`(중요 변경만), 세부는 Git 커밋 |

- 대화창에서 나온 결론도 Issue/PR 코멘트에 옮겨 적어야 상대 AI가 볼 수 있다. 기록되지 않은 합의는 합의가 아니다.
- 한 Issue는 한 주제만 다룬다. 결론이 나면 `합의`/`미합의` 요약 코멘트를 남기고 닫는다.

## 2. 의견을 남기는 방식

모든 의견 코멘트는 아래 네 줄을 갖춘다(짧아도 된다).

```
작성자: ChatGPT | Claude Code | 사용자
의견: 한두 문장
근거: 확인한 코드·데이터·문서 위치(파일:줄, 쿼리, 링크), 직접 확인하지 못한 것은 '미확인'
검증: 실행한 테스트·측정과 결과(없으면 '없음')
```

- 상대 의견에 반대할 때는 반대 이유를 근거와 함께 적고, 가능하면 둘을 가를 검증 방법을 제안한다.
- 상대 AI가 쓴 코드·수치는 그대로 믿지 않고 직접 읽거나 재현해서 확인한 뒤 '검토함/재현함'을 적는다.
- 추정을 확정처럼 쓰지 않는다. 단위·필드가 검증되지 않았으면 미확인으로 표시한다(`CLAUDE.md`).

## 3. 합의와 충돌

1. 의견이 충돌하면 **근거로 판단**한다(재현 가능한 측정·코드·문서 > 일반론). 작성자가 누구인지는 근거가 아니다.
2. 두 AI가 같은 결론에 이르면 `합의: 내용, 근거 요약, 남은 위험`을 Issue에 적는다.
3. 근거로 가를 수 없으면 `미합의`로 두고 양쪽 입장·근거·가를 방법을 한 코멘트에 정리해 **사용자에게 보고**한다. 어느 한쪽이 임의로 진행하지 않는다.
4. 합의는 코드 변경 승인이 아니다. 변경은 PR에서 상대 AI(또는 사용자)가 검토한 뒤 병합한다.

## 4. PR 규칙

- 한 PR은 한 목적. 요청 범위를 넘는 리팩터링을 하지 않는다.
- 본문에 **변경 파일, 검증 결과(실행한 테스트·측정), 미확인 항목**을 적는다. 병합 뒤에는 PR 번호와 병합 커밋 SHA를 `docs/WORK_HISTORY.md`에 남긴다(중요 변경일 때).
- 작성한 AI가 아닌 쪽이 PR을 읽고 `검토 의견`을 남기는 것을 기본으로 한다. 검토에는 최소한 (a) 의도와 실제 변경이 맞는지, (b) 테스트가 변경을 실제로 잡는지, (c) 기존 기능·데이터가 유지되는지를 확인한다.
- 키·토큰·계좌번호·개인정보·`.env`·DB·로그는 코드·문서·Issue·PR·코멘트 어디에도 올리지 않는다.

## 5. 실계좌 자동매매는 사용자 승인 필수

- PC 실계좌 엔진(`live_engine.py` 등)·실주문 설정·자금 한도를 바꾸는 일은 두 AI가 합의했더라도 **사용자의 명시 승인**을 받은 뒤에만 한다. 승인 범위는 해당 건에 한정되며 다른 변경으로 확장되지 않는다.
- 승인 전 단계(분석·시뮬레이션·읽기 전용 점검·기록 추가 제안)는 자유롭게 한다. 분석에 계좌 조회가 필요하면 읽기 전용 도구만 쓴다.
- `quant-autotrade/` 병합·배포·실주문은 `CLAUDE.md`의 승인 규칙을 따른다. 엔진 변경은 백업·롤백 방법·적용 시점을 PR/문서에 적는다.

## 6. 비용·자동화 제한

- AI API 호출, 유료 자동화, 별도 서버 구축을 하지 않는다. 두 AI는 사용자가 이미 쓰는 구독 도구(ChatGPT, Claude Code)로 GitHub를 읽고 쓴다.
- GitHub Actions는 기존 테스트·점검 실행 용도로만 쓴다(`api-probe.yml`, `page-speed.yml` 등 수동 실행 도구 포함). AI를 호출하는 워크플로를 추가하지 않는다.

## 7. 시작할 때 읽을 것

`docs/README.md` → `CLAUDE.md` → 작업 관련 문서 → `docs/WORK_HISTORY.md` 위쪽(통독 금지, `grep` 사용) → 관련 Issue/PR 코멘트.
