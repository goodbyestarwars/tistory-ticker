같은 PC에서 이후 대조한 Tistory 홈HTML0.25초, Pages 공통JS0.38초, auth0.66초였다. VM loopback에서도 health8초 timeout/auth3.25초가 재현됐고, 후속 health는0.25초로 회복됐다. 코드 적용 전 자연 회복이므로 후속 회복을 이번 패치 효과라고 주장하지 않는다. 인터넷/브라우저 문제만으로는 설명할 수 없는 서버 내부 간헐 지연이 확인됐다.

브라우저 최초 측정의 DOMContentLoaded는 navigation start 대비 약1.11초, FirstMeaningfulPaint 약1.64초였다. Performance 계측은 짧은 표본이며 모바일 LCP/INP 또는 모든 사용자 대표값이 아니다. UI가 먼저 나오고 데이터가 뒤늦게 채워지는 병목과 맞지만 브라우저 문제 전체가 없다는 증거는 아니다. CPU Profiler는 현재 연결에서 지원되지 않았고 전체 렌더 프로파일을 확보했다고 보고하지 않는다.

## VM 읽기 전용 상태

운영 API 프로세스는 재시작 없이 유지됐다. e2-micro/메모리 약954MB 환경에서 가용 메모리 약396MB, 사용 swap 약356MB, 디스크41% 사용/17GB 여유였다. 디스크 용량 고갈은 아니다. vmstat 짧은 표본의 CPU idle0%, I/O wait49~50%를 확인했다. 후속 PSI60초 평균은 CPU대기 약41%, IO대기 약56%, 메모리대기 약26%였다. 지표 정의가 서로 다르므로 이 비율들을 합산하지 않는다.

apt-get·릴리스 검사 작업의 동시 실행도 관측했지만 이후 사라졌다. SSH 로그인에 따른 검사 부하와 운영 수집/DB/네트워크 경합을 독립 분리하지 못했으므로 특정 업데이트 하나가 지연의 유일 원인이라고 단정하지 않는다. OS 업데이트를 끄거나 실행 중인 프로세스를 중단하지 않았다. 특정 endpoint가 worker pool을 고갈시켰다는 가설은 thread stack/시간대별 대기 지표가 없어 미확정이다.

## 최소 프런트 개선

- quick-indices.js의 공통 futures 조회에 기존 stored_only=true 계약을 사용한다. 백그라운드 수집기가 갱신한 DB 시세·chart·updated_at/stale/source_delay를 유지하고, 초기 화면 요청에서 추가 환율 공급자 호출을 기다리는 경로를 피한다. 원본 폴러·갱신 주기는 바꾸지 않는다. skin-main의 공통 모듈 부재 fallback도 동일 계약을 사용한다.
- 홈의 home-session-chart는 미국 지수/야간선물 전용이며 국내 화면에서는 숨겨져 있었다. 국내·휴장·숨김 문서에서는 이 요청을 보내지 않는다. 국내 초기1회+분당1회를 없애고 미국 탭 전환 시 즉시 로드한다. 미국 차트·가격·30분봉·기존 동시요청 가드는 보존한다.
- 공통 NineHttp/QuickIndices 및 HomeMarketSelection을 재사용한다. VM/API서버/DB/수집기/주문 코드·로그인 인증·기존 디자인·매매 조건은 수정하지 않는다.

이 패치는 불필요한 대기를 줄이는 완화책이며 서버 자원 경합을 완전히 해결하는 조치가 아니다. 저장 시세는 기존 수집 주기에 따른 지연이 있을 수 있고 수신시각을 실시간으로 조작하지 않는다.
