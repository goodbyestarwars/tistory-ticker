## 데이터 경계와 VM 영향

정적 파일은 `window.DCF_INDEX=...;`, `window.DCF_MARKETS=...;`, `window.DCF_FILES={기업코드:자료};`. 브라우저는 JSON 부분만 파싱하며 실행하지 않는다. 최초 검색 인덱스만 다운로드, 선택 후 해당 기업 파일 하나만 로드. 15초 시간 제한·AbortController·응답 토큰으로 이전 기업/모드 응답을 무시한다. 동일 기업 수정본은 페이지 메모리에 보존하며 새로고침 후 저장은 이번 범위 밖이다.

기존 `deploy_check.sh`의 VM 재시작/검색 재스캔 감시가 `data/` 전체를 포함하므로 자료는 **`dcf-data/`에 저장**한다. 새 상시 프로세스·타이머·VM API·SQLite 쓰기 없음. 기존 VM DART 클라이언트를 로컬/Actions에서 import하고 공개 매핑 캐시는 로컬 `work/`로 재지정한다. VM의 Git 체크아웃에는 새 정적 파일이 보관될 수 있어 디스크의 Git 파일 보관량은 증가한다. DCF 페이지 요청/계산은 VM CPU·메모리·API 호출에 추가 작업을 만들지 않는다. 운영 전체 부하의 장기간 인과 대조는 미검증이다.

초기 키는 기존 VM 환경설정에서 메모리로만 전달해 PC에서 수집했고, 정기 갱신용 키는 해당 저장소 Actions의 `DART_API_KEY` Secret으로 등록했다. 공개 코드·정적 자료·로그에 키 없음. corpCode API는 실제 `800` 점검중, 재무 API는 `000` 성공이었다. 기존 공개 기업코드 캐시를 재사용해 수집했다. 다운로드 실패 때 기존 공개 캐시가 있으면 유지하며 없으면 실패를 명시한다.

콜드 Actions 러너도 동일 공개 매핑을 `index.js`의 `corpCodes`에서 부트스트랩한다. 공개 기업번호만이며 재무값을 만들어내지 않는다. 이 매핑 보강으로 인덱스 크기는 최초411KB에서 증가한다. `dcf/index.html`은 티스토리 관리자 로그인 전에도 사용할 수 있는 독립 Pages 화면이다.

## 정규화와 계산

- 규격 `schemaVersion:1`, 자동 자료 통화 KRW·API 원금액 단위 원. 기본 표시 억원, 원/천원/백만원/억원 환산 시 원금액 유지. 직접 입력 USD/EUR은 해당 통화의1/천/백만/억 단위, 자동 환율 변환 없음. 주식 수 주, 주가 통화/주, 세율 비율 저장·% 표시.
- 직전 완료 달력 사업연도5칸과 ΔNWC 선행1년 수집. 사업보고서 `11011` 당기만 사용; 분기 누적·비교표시 값을 다른 연도 원본처럼 사용하지 않는다. 미공시 칸은 공란이며 오래된5년을 최근5년으로 밀지 않는다. 비12월 결산의 가장 최근 완료 사업연도는 원문 수동 확인 필요.
- 최신연도 CFS 우선, 사업보고서 존재를 확인하고 CFS가 없을 때만 OFS. 과거 전체도 같은 기준을 유지하고 없는 연결연도를 별도로 메우지 않는다.
- `list.json last_reprt_at=Y` 사업보고서의 결산연도별 최신 접수 선택. 계정 응답 접수번호 일치만 자동 확인. 불일치는 확인 필요. 복잡한 철회/정정명령의 원문 자동 판정은 없음.
- 표준 ID와 재무제표 구분 우선. 비표준 정확한 이름은 확인 필요. 중복·상하위·부문 계정은 임의 첫 행 선택 금지. 통화/값 미확인은 null, 실제0은 값으로 유지.
- CAPEX=유형·무형 취득 지출 양수 합계. 처분과 상계하지 않는다. 구성값 누락을0으로 채우지 않는다. D&A 합계와 분리계정을 중복 합산하지 않으며 분리계정은 둘 다 확보해야 합산한다.
- 법인세비용/세전이익은 정상세율 후보로만 표시; 세전적자/0·0~100% 밖은 미확보. 납부(환급 포함)는 별도이며 FCFF 세율과 같다고 보지 않는다.
- NWC=채권+재고−채무 후보는 포괄 기타채권/채무 포함 가능성이 있어 수동 확인. ΔNWC=같은 기준 당기−전기. 전년 없으면 미확보.
- 총차입금은 차입금·사채·리스 등 구성 누락/중복 확인 필요. 유동부채/부채총계로 대체하지 않는다. 순차입금과 비영업자산·비지배지분 등 가치 조정은 사용자 검토.
- 주식총수 `istc_totqy`/`tesstk_co`/`distb_stock_co`의 보통주행만 사용. 발행−자기=유통을 대조하되 이후증자·희석·다른주식 권리 검토 전에는 계산필수값으로 자동 승인하지 않는다.

각 필드는 value/status(auto,user,review,missing)/reason/sources를 보존한다. 출처는 접수번호·계정ID/명·표구분·API통화·원금액·단위, 연도는 보고서명·접수일·연결/별도·원자료행을 보존한다. 계산 입력과 산식을 출처 펼침에서 확인할 수 있다. 인쇄 보고서의 배율은 API 원금액과 별개이며 확인하지 않은 천원/백만원 인쇄 배율을 주장하지 않는다.

FCFF=EBIT×(1−세율)+D&A−CAPEX−ΔNWC. OCF−CAPEX는 비교값으로 분리. 확인 필요/미확보 필수값은 자동 DCF 차단. 업종·지주회사 구조·주식 권리·희석·비지배지분 검토 필요. 금융업과 우선주는 일반 FCFF 자동 평가 차단. 기준 FCFF≤0은 회복근거와 향후연도별 입력을 요구; 최종 예측 FCFF≤0은 영구성장 적용 차단. WACC>영구성장률·WACC>0·성장률>−100%·주식수>0 검증. 5년 할인 후 기업가치−조정 순차입금을 조정 주식수로 나눈다.

직접 입력은 별도 상태. 수정한 파생값은 부모계정 변경에도 보존하며 원본복원은 확인 필요/미확보 상태까지 복원. 최초 진입은 금융값/가정 모두 공란이다.
