# 1시간 방향 v6 전진 성과 검증

2026-10-09. `hour_direction_engine.py`와 `hour_candidate_engine.py` 계산식은 수정하지 않는다. 예측이 나온 당시 입력과 출력은 불변으로 보존하고 결과만 별도로 붙인다. 현재 표본은 사용자 수동 선택 표본이며 전체 시장/독립 표본/수익 우위가 검증됐다는 뜻은 아니다.

## 평가 정책 `krx-tick-60m-v1`

- 기준 시각 T0: 공개 방향 `checkedAt`(4개 입력 수집 직후). 전체 작업 완료 시각으로 대체하지 않는다.
- 기준가 P0: 기존 v6 `referencePrice`(KIS KRX 최신 체결가). 실제 주문 체결가가 아니다. 원래 기준가가 없으면 평가 제외하며 입력의 다른 가격으로 보정하지 않는다.
- 목표 T1=T0+60분. 초 미만 원래 시각은 그대로 보존한다. KIS 체결시각은 초 해상도이므로 T1와 같은 초의 관측을 `exact`로 분류한다. `offset_sec`에는 원래 T1와의 실제 차이를 보존한다.
- 동일 KIS `inquire-ccnl`, TR `FHKST01010300`, `FID_COND_MRKT_DIV_CODE=J`의 체결만 사용한다. NXT/통합/미국/일봉/분봉 종가는 대체 가격으로 사용하지 않는다.
- 선택 우선순위: 같은 초 → 목표 직전 10초 이내의 가장 늦은 관측 → 목표 직후 60초 이내의 가장 이른 **확보된** 관측. 정확한 체결 전체 순서를 보유하지 않으므로 직후의 실제 최초 체결이라고 보장하지 않는다. 반환 체결 목록이 짧거나 급속 거래로 중간 체결이 빠질 수 있다.
- 선택 초에 서로 다른 체결 가격이 존재하면 `ambiguous_trade_second`로 제외한다. 어느 가격이 그 초의 마지막인지 추정하지 않는다. 같은 가격 중복은 중복 관측으로 제거한다.
- 허용 범위 밖, 가격/체결량/호가단위 오류, 공급자 미래 시각, 명시적인 다른 거래일 데이터는 사용하지 않는다. 공급자 날짜가 없는 행은 장중 수신일+HHMMSS로 해석하며, 과거 미평가 건을 다음날 현재가로 채우지 않는다.
- T1+90초 이후 한 번만 확정한다. T1+60초까지의 가격을 받을 수 있도록 30초 수집 여유를 둔다. 적합한 관측이 없으면 `no_eligible_trade`, 기준가가 없으면 `missing_reference`. 공급자 실패/VM 중단은 적중 또는 실패로 꾸미지 않고 제외한다.
- 장외 신규 요청은 보존하되 `scope=outside-window`, 정상 시간 요청과 공급자 오류/보류는 `scope=in-session`. 기본 보류율은 장중 요청만 대상으로 한다. 원래 공급자 호출 전 실패한 HTTP 409/429/503은 예측이 생성되지 않았으므로 성과 분모에 넣지 않는다.

## 통계 정의

`change_pct=100×(P1/P0−1)`. 실제 방향은 >0 상승, <0 하락, =0 동률. 적중률=상승/하락 방향 일치 건수÷평가 가능한 상승/하락 건수. 동률은 적중이 아니며 분모에 포함한다. 제외·진행중·판단 어려움은 적중률 분모에 포함하지 않는다.

보류율=장중 `unclear` 건수÷장중 전체 예측 건수(자료 누락으로 평가 제외된 unclear도 포함). 방향별 예측 수·평가 수·제외 수·진행중 수·동률 수를 함께 제공한다. unclear도 가격과 기준가가 확보되면 실제 가격 변화는 저장하지만 매수/매도 적중 또는 방향 수익으로 바꾸지 않는다.

상승 가상 방향 수익=`change_pct`, 하락 가상 방향 수익=`−change_pct`. 가격 변화율과 방향 수익률을 별도로 제공한다. 하락 값은 실제 공매도/매수 수익이 아니다. 수수료·세금·슬리피지·대차 비용을 제외한 가상 수치다.

평균 수익률=평가된 방향 수익의 산술평균(동률 0 포함). 손익비 `payoffRatio`=양수 방향 수익 평균÷음수 방향 수익 절댓값 평균. `profitFactor`=양수 합÷음수 절댓값 합. 손실 또는 필요한 표본이 없으면 무한대/0으로 꾸미지 않고 null. 통계는 모델 버전별로 항상 분리하고 KST 확인 시각의 1시간 구간·종목·판정 방향으로 추가 분리 가능하다. 현재 반복/겹치는 60분 표본의 종속성, 비용, 신뢰구간을 보정한 성과는 아니다.

## 저장·복구·원시 지표

`hour_validation.db`(환경변수 `HOUR_VALIDATION_DB`로 경로 변경 가능), WAL, synchronous FULL, SQLite page cache 1MiB, 접속 timeout 2초. `predictions`와 `outcomes`는 UPDATE/DELETE 차단 트리거, 예측 내용 해시 PK와 결과 prediction_id PK로 중복 저장/평가를 방지한다. 예측 원본 verdict·기준 시각/가격·모델·이유와 zlib 압축 원본 입력을 저장한다. 별도 `observations`는 사용 가능한 후보 체결과 공급자 원시 필드·수신시각·출처를 보존한다. 실제 선택된 관측은 결과 evidence에도 복사해 남긴다. `attempts`는 재시도 간격을 보존한다.

분석 지표는 최종 v6 metrics에 더해 `strengthRaw`, `referenceTradeAt`, `fiveMinuteChangePct`, `tradePriceToleranceRaw/Pct`, `tradeVsClosedPct`, `volumeAccelerationRaw`, 최근 3봉 저점/고점, 확정 저점 피벗을 별도로 저장한다. 분봉 원본은 전부 남으므로 고점 피벗·다른 문턱/가속/기간도 미래 분석에서 재계산할 수 있다. 분석 지표를 v6 판정에 넣지 않는다.

기존 JSONL은 그대로 유지한다. 최초 시작 시 `.1`과 현재 파일을 `hour_validation_archive/`에 바이트 그대로 복사한 뒤 v6 기록만 새 DB에 멱등 가져온다. v3~v5는 보관본에 남기며 v6 성과와 합치지 않는다. 과거 입력/판정을 다시 계산하지 않는다. 과거 만기 결과가 없으면 제외한다.

새 DB를 재배포 복사/초기화 대상에 넣지 않는다(기존 deploy_check.sh는 *.py만 복사). 재시작 후 미평가 행을 다시 읽고, 이미 저장된 적합한 관측이 있으면 결과를 확정한다. 수집 기회를 놓친 건은 현재 가격으로 소급 평가하지 않는다. 장외 기존 maintenance에서 기존 backup_sqlite의 VACUUM INTO+무결성 검사로 최근 7개 백업 유지. 원본 예측/결과는 자동 삭제하지 않는다. DB+WAL 512MiB 도달 시 새 예측 저장 실패를 `validationRecorded:false`로 노출하고 운영자가 아카이브 후 용량 정책을 결정해야 한다. 백업 7개는 추가 디스크 용량을 쓴다.

디스크 장애 복구는 서비스를 정지한 상태에서 가장 최근 무결성이 확인된 `backups/hour_validation_*.db`를 새 경로에 복원하고 `HOUR_VALIDATION_DB`를 그 경로로 설정한 후 재시작한다. 손상 원본을 먼저 보존한다. 복원 시점 이후 관측/예측은 백업에 없을 수 있다. 이는 같은 디스크 백업으로 VM 디스크 자체 손실까지 보장하지 않는다. 원시 기록 export를 외부에 보관할 수 있다.

## 기존 수집 재사용·서버 부하

기존 `kis_client._get_domestic_quote`의 KRX 체결 응답을 재사용한다. 만기 근처의 해당 종목이 있을 때만 저장한다. 분봉 캐시는 체결시각이 없고 미완결 봉/시장이 다를 수 있으므로 평가 가격으로 재사용하지 않는다.

기존 VI `circuit_breaker` 20초 스레드의 callback으로 평가한다. 신규 프로세스·스레드·systemd timer는 없다. 만기 없는 tick은 외부 요청 0회. 필요한 만기 종목만 중복 제거해 tick당 최대 2종목, 종목별 최소 20초, KIS 요청 4초 timeout 및 기존 수동 요청 시작 간격을 공유한다. 최악의 명목 외부 요청 상한은 6회/분(20초×2); 실패/누락 때 제한 구간 안에서 재시도한다. 토큰 만료의 기존 재발급/재시도는 별도다. 기존 체결 관측으로 전체 허용 창을 커버하면 추가 요청을 생략한다. 한 callback의 통상 HTTP 대기 상한은 2×4초이며 토큰 발급/기존 재시도로 늘 수 있다. 기존 VI 주기는 그만큼 지연될 수 있다. 소수 pending 행만 메모리에 올리고, 만기 확정 최대 200건/tick, 통계는 SQL 집계, raw export 최대 100건/page, 그룹 최대 1000개로 제한한다.

## API

- `GET /hour-direction`: 기존 필드/계산 유지, `predictionId`, `validationRecorded` 추가. 기존 `recorded`는 JSONL 저장 성공을 뜻한다.
- `GET /hour-direction/performance`: 공개, no-store, IP 분당10회, 외부 조회 없음. `model`, `code`, `group_by=model|hour|code|direction`, `start`, `end`(KST 날짜, start 포함/end 제외), `scope=in-session|outside-window`. 모델별 그룹과 totals·제외 사유·가격 선택 방식/평균 절대 시간 오차를 제공한다. `validated:false`는 통계를 만들었다고 모델 우위가 검증된 것으로 바꾸지 않는다는 의미다.
- `GET /hour-direction/records`: 기존 X-API-Key 인증, no-store, `limit`1~100, `after`는 응답 nextCursor를 그대로 전달한다. 생성시각+ID 순서로 원본 verdict·snapshot·지표·결과·체결 근거를 export한다. 인증키는 브라우저에 넣지 않는다.
