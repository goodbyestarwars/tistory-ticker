# 검색·관찰 스캔 효율화 (2026-10-20)

## 경계

실계좌 A/B 조건·20칸 구독·고정 후보 우선순위·주문·예산·손절/익절은 유지한다. `kiwoom_9pay_observer.py`는 변경하지 않았다. `kiwoom_9pay_live.py`는 기존 응답을 읽는 관찰 훅만 추가한다. 후보 확장은 새로운 WS 구독이나 A/B 신호를 만들지 않는다. 기존 5개 메뉴·원래 검색기별 이력과 성과 네임스페이스는 유지한다.

## 계측 범위와 한계

- 기존 KIS 사전포착: 거래량/증가율/거래대금 순위 3 + 상승률 1 = 회당4 읽기 함수 호출, 30초 간격. 실제 주기는 처리시간+30초다. 키움 A/B: 거래량/거래대금 2건, 60초 간격. 별도 사이드바는 거래량/상승/하락 3건, 30초 간격이다. 인증·오류 재시도·다른 화면의 API는 이 숫자와 별개다.
- 기존 KIS 표본을 A/B에서 30초마다 읽는 경로는 메모리 읽기이며 새 외부 호출이 없다. 일봉은 daily_scan/rescan 공통 `scan_stock`을 사용한다. 기술 후보가 생겼을 때만 시총을 조회하는 기존 관문도 유지한다.
- 새 `/health/scanner`는 프로세스 시작 이후 순위 읽기 함수 호출 수·오류·누적/최대시간, 사이드바/전일봉/20일 통계/일봉 메모리 캐시 적중/미적중, 이미 받은 순위 원행/고유종목/중복행/관측간격을 제공한다. HTTP 재시도까지 센 네트워크 총량이나 전체 KIS·키움 호출 수라고 부르지 않는다.
- 20칸 누락률의 분모는 **같은 조회에서 받은 유효 순위 후보 풀**이다. 전 시장 신호 누락률·수익 기회 누락률은 측정하지 못한다. 순위 밖 데이터가 없고 과거 전체 응답도 보존되지 않았다. 부분 장애 때는 누락률을 null로 두고 정상 관측 누적에 넣지 않는다.
- 배포 전 과거 rank 로그398회(2026-10-19 09:00:24~15:35:37 KST), 최대 실제 후보19개, 고정 후보로 인한 별도 capacityOmitted0건. 전체 원행이 없으므로 이를 전체 누락0%로 해석하지 않는다.

## 관찰 후보

키움 기존 거래량60행+거래대금60행, KIS 기존 최대120행을 종목코드로 합친다. 기존 인버스/레버리지/금리·현금성 제외 정책은 관찰에도 적용한다. 주가×누적거래량을 **거래대금 대용값**으로 명시하며 단위 미검증인 원 거래대금을 원화처럼 쓰지 않는다.

관찰 정렬 점수 = 거래대금 대용값의 순위점수(0~1) + min(같은 소스 직전 관측 대비 거래량 증가율,100)/100 + 신규 순위 진입이면0.25. 증가율은 같은 날·정상응답·180초 이내·누적량 비감소일 때만 계산한다. 첫 실행·날짜변경·오류 후·긴 공백에는 신규 진입을 추정하지 않는다. 새로 순위에 등장한 종목의 이전 거래량을0으로 만들지 않는다. 점수는 연구용 정렬이며 수익성/매수조건이 아니다.

실제 기존 20칸 선택과 고정 로직이 끝난 뒤 교집합/빠진 코드·비율을 별도 기록한다. 소스별 최대240개 표시, 상태JSON 및4MiB×2 JSONL 회전 로그만 사용한다. 토큰·계좌·주문·원 프레임은 저장하지 않는다. 새 스레드/타이머/DB는 없다. 관찰 저장 실패는 거래 흐름에 예외를 전파하지 않으며 health에 오류를 표시한다.

## 계산과 재무

- 같은 종목의 동일한 읽기 전용 일봉 입력에서만 이동평균 결과를 공유하고 호출이 끝나면 해제한다. 서로 다른 길이/시작점의 창은 누적합 순서가 달라지므로 합치지 않는다. 원래 슬라이딩 합의 부동소수점 연산 순서를 유지한다. 반환 배열은 복사해 공유 배열 오염을 막는다.
- 입력 값 전체를 키로 비교하던 첫 캐시안은 실제40종목에서 약8.8% 느려 제거했다. 동일 입력 객체만 공유하는 안은351회 요청 중19회 재계산을 줄였고(5.4%), 7회 교차측정 중앙값51.72→50.72ms(약1.9%). 전체 스캔 시간이2% 줄었다고 일반화하지 않는다. Python 추적 피크131→152KB, 종목 단위 해제. 판정 결과는 정확히 같았다.
- 중장기 최신 공시 확인은 기존 maCloudBreakout 기술 후보에만 적용한다. 기본 재무/배당의 기존90일 갱신은 유지하고, 비후보의 오래된 screening 증거 날짜를 새 날짜로 바꾸지 않는다. 후보는7일·필요 보고기간·최신 공시 일치·연간/단독분기 이익 관문을 그대로 통과해야 한다. 누락/오래된 자료는 기존 사유 집계로 제외된다. 우선후보와 일반 순회가 겹쳐도 같은 실행에서 한 종목만 갱신한다.
- 배포 전 실제 캐시2,648건·기술후보8건에 대한 **갱신 결정 재생**: 기존 방식2,614건, 변경 방식1건. 2,613건은 기본 자료는90일 이내인데 비후보의 screening이 오래돼 불필요하게 전체 재무를 다시 읽게 되던 경우다. corp-map·시간예산을 반영한 실제 호출 절감량은 아니다. 실제 호출 수는 장중/배치 운영 관측이 필요하다.

## 시각·장애 표시

일봉 날짜(dataAsOf)와 스캔 확인시각(lastObservedAt)을 구분한다. 거래소 원천 전송시각은 미확인이므로 sourceAsOf=null이다. 장중 행은 실제 마지막 표본시각을 사용한다. API 일부 실패도 지우지 않고 기록하며,90초 초과 표본/장외/장애/순위 갱신120초 초과는 신규 실시간 포착으로 표시하지 않는다. 원래 패턴/단계 태그와 기록은 남기고 마지막 관측·기록을 명시한다. 일봉36시간 초과 또는 확인시각 누락도 신규 표시 대신 기록으로 표시한다. 휴일에 잘못 신규로 보이는 일을 피하는 보수적 표시 기준이며 거래 판정에 쓰지 않는다.
