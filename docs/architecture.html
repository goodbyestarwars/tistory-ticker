tistory-ticker 시스템 구성도

다른 AI(ChatGPT 등)에게 가벼운 작업을 맡길 때 붙여넣을 인프라 요약. 파일별 상세 이력은 저장소의 CLAUDE.md, 이 내용의 원본은 ARCHITECTURE.md·API_REFERENCE.md에 있음 — 이 페이지는 그 시각 요약본.

작업 시작 순서

단계위치로딩 시점
① 최소 공통 규칙 CLAUDE.md 항상 먼저
② 작업 종류별 절차 .claude/skills/*/SKILL.md
(feature-development · bug-fix · ui-improvement · deploy · tistory-post-html)		 작업 종류가 정해지면 해당 skill 1개만
③ 건드리는 경로의 규칙 .claude/rules/frontend.md
.claude/rules/backend.md		 그 경로 파일을 실제로 고칠 때만
④ 깊은 배경지식 ARCHITECTURE.md · API_REFERENCE.md · docs/UI_GUIDE.md 필요한 절만 그때그때

전부 한 번에 읽지 않고 필요한 것만 읽어 시작 토큰을 줄이는 게 목적(docs/README.md 참고). 과거의 긴 CLAUDE.md 이력은 git log -p -- CLAUDE.md로 조회.

개발용 MCP — 프로덕션 아님

⚠ VM에는 MCP가 없다

VM(goodbyestar.cloud)은 순수 FastAPI REST 서버다. "MCP"는 개발 중 Claude Code 세션에서 API 문서/응답 필드를 확인할 때만 쓰는 로컬 도구이며, 사용자의 Windows PC에 등록돼 있다 — 서비스 트래픽과는 무관.

  • kis-code-assistant-mcp — 한국투자증권 공식 코드검색 MCP. C:\Users\goodb\.mcp-servers\open-trading-api\MCP\KIS Code Assistant MCP에 등록. TR 코드/파라미터 검색 전용, 실호출은 못 함.
  • mcp__kiwoom__* — 키움 REST API의 실제 응답 필드를 실계정으로 확인할 때 쓰는 MCP.

ChatGPT에는 이 MCP가 없으므로, 키움/KIS 파라미터가 필요한 작업은 API 문서를 새로 찾게 하기보다 이미 검증된 kiwoom_client.py / kiwoom_market.py / kis_client.py의 기존 패턴을 그대로 따라 하게 시키는 편이 안전하다.
