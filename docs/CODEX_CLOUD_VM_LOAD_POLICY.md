# Codex Cloud 우선 개발 · GCP VM 부하 최소화 운영안 (2026-10-27)

> **상태:** Codex Cloud와 운영 VM의 **작업 경계를 정의하는 문서**. 저장소 문서화는 클라우드 환경 게시, 서버 설정 변경 또는 실측 부하 감소를 의미하지 않는다.
> 공통 정책은 [CLAUDE.md](../CLAUDE.md), 현행 스케줄은 [SCHEDULER_CONSOLIDATION_2026-10-20.md](SCHEDULER_CONSOLIDATION_2026-10-20.md), 백엔드 운영 계약은 [API_OPERATION_SPEC.md](API_OPERATION_SPEC.md)가 원본이다.

## 목적과 경계

- **OpenAI Codex Cloud**: GitHub 작업 브랜치에서 코드 탐색·수정·테스트·정적 분석·시뮬레이션·PR 준비를 한다. 테스트는 로컬 fixture/모의 응답을 기본으로 한다.
- **GitHub Actions/Pages**: 기존 CI 및 정적 파일 전달을 재사용한다. 신규 상시 워크플로나 고빈도 스케줄은 만들지 않는다.
- **GCP e2-micro 1GB VM**: 기존 FastAPI, 시장 데이터 취득·캐시·배치·모니터링의 **운영 전용**으로 유지한다. 개발을 위해 추가 프로세스, 브라우저, 테스트 서버, 크롤러, 자동 재시작 작업을 띄우지 않는다.
- **Windows PC 실계좌 엔진**: 이 문서 범위 밖이다. 주문·재시작·매매 규칙·활성화/중단·예약 작업은 사용자의 해당 변경에 대한 구체적 승인이 없으면 수정하지 않는다.
- **운영 배포**: 기본/배포 브랜치 `master` 병합 시 자동 적용될 수 있다. 부하 최적화 코드는 **작업 브랜치 → PR 검토 → 테스트·안전 승인 → 장외 병합/배포 확인** 순서로 진행한다. Codex Cloud가 자체적으로 운영 VM을 대체·배포하는 것은 아니다.

## Codex Cloud 환경 준비 (최소 권한)

1. Codex Cloud에서 `goodbyestarwars/tistory-ticker` 저장소를 연결하고 별도 개발 환경을 **생성·테스트·게시**한다. 환경 게시 자체는 이 문서 작업과 별개로 사용자 UI에서 수행한다.
2. `AGENTS.md` → `CLAUDE.md` → 작업에 필요한 원본문서만 읽는다. 전체 전종목 데이터, 대형 DB, 이력 전체를 환경에 복사하지 않는다.
3. 설정 스크립트는 테스트에 꼭 필요한 의존성만 설치한다. GCP SSH, root/sudo 배포 권한, 실거래 계좌·키움/KIS·Google OAuth 운영 자격 증명, API 비밀키, `.env`, DB 원본, 개인 로그를 Codex 환경에 넣지 않는다.
4. 테스트가 운영 API나 공급자에 자동 연결되지 않게 fixture/mock을 기본값으로 한다. 실제 운영 응답 확인이 필요하면 **읽기 전용·낮은 빈도·명시적으로 승인된 범위**로 제한하고 키나 개인정보를 저장하지 않는다.
5. 결과는 브랜치/PR에 남긴다. 실제 데이터 수집·실계좌 주문·배포는 Codex 개발 테스트의 성공을 근거로 자동 실행하지 않는다.

### 변경 전 근거

- `docs/SCHEDULER_CONSOLIDATION_2026-10-20.md`의 2026-10-19 전종목 스캔: 3,918종목, **3시간 31분 31초**. 누적 API 응답 대기 약 78%, 의도된 간격 약 16%를 차지했다. 공급자 간격을 줄이거나 병렬화해 단축한다는 가정은 금물이다.
- 공용 예약·잠금/재시도/타임아웃 계약이 이미 구현되어 있다. 같은 목적의 새 스케줄러/캐시 계층을 만들지 않는다.
- 위 값은 과거 기준선이며 **현재 운영 CPU/RSS/스왑·트래픽 실측은 아니다**.

## 변경 전후 실측 및 합격 조건

작업 수행자는 아래를 **기준선/변경 후 동일 거래일 조건**으로 기록한다. 공개 엔드포인트 `/health/load`, `/health/schedules`, `/health/latency` 또는 승인된 VM 내부 journal을 사용하고, 명령줄·토큰·계좌·IP·원시 로그는 공유하지 않는다.

1. 서버: loadAvg 1/5/15분, MemAvailable/Swap 사용량, FastAPI/배치 RSS, 페이지 응답 지연(p50/p95), 오류율·OOM/재시작.
2. 수집: 공급자별 일일 호출 건수·예산 준수, 캐시 적중/중복 요청, 스캔 대기/실행 시간·완료 종목 수, 마지막 데이터 기준일과 신선도.
3. 업무: 중복된 수동 배포·테스트/재실행 횟수와 운영자의 개입 횟수. Codex Cloud에서 실행된 검사와 GCP에서 실행된 검사 구분.
4. 비교: 동일 범주의 거래일 **최소 3회** 관찰을 목표로 하고, 예외(장애·휴장·배포)를 표시한다. 표본이 없으면 개선율을 주장하지 않는다.

**합격:** 기능·시세 기준일·시장 구분·기존 캐시/DB/백업·실계좌 안전 게이트·예약 종료시간이 보존되고, CPU/스왑·API 호출 또는 운영 수작업 중 적어도 1개가 실측으로 개선되며 다른 지표가 의미 있게 악화되지 않을 것.

**중단·복구:** 지연 증가, 공급자 제한 위반, 오류·스왑·잠금 악화, 지연/결측을 정상 처리하는 회귀가 있으면 적용을 중단하고 PR/배포 전 버전으로 되돌린다. 거래중 VM 재시작·실거래 조작은 하지 않는다.

## 이번 문서 변경의 한계

- 실제 Codex Cloud 환경 **생성·게시 안 함**.
- GCP에 SSH 접속하거나 프로세스를 조정하지 않았으며, 현시점 운영 부하를 직접 측정·감소시키지 않았다.
- 위험도가 있는 런타임·수집·예약 작업 변경은 기준선 확보 후 별도 PR에서 한다.
