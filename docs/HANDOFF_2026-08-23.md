## 4. 코딩할 때 주의할 점 (이번 세션에서 얻은 교훈)

### 데이터/계산 관련

- **섹터·업종 단위로 여러 종목의 배수(PER/PBR 등)를 집계할 때는 절대 단순 산술평균을
  쓰지 말 것.** 이익이 0에 가까운 종목 하나만 있어도 PER이 수천 배로 튀어 평균 전체를
  왜곡한다(효성화학 사례). **중앙값(median)을 기본으로 쓰고**, 정말 평균이 필요하면
  이상치를 먼저 걸러내거나(예: PER 상하위 N% trim) 그 이유를 주석에 남길 것.
- **KIS/키움 API 응답 필드명은 절대 추측하지 말 것.** 이번 세션에 두 건이나
  "그럴듯한 이름을 여러 개 나열해 순서대로 시도"하다가 실제 필드명이 목록에 없어서
  기능이 통째로 죽어있던 사례가 나왔다(`option_flow.py`의 `acpr`, 이전 세션의 다른 TR도
  유사). `kis-code-assistant-mcp`(user-scope 설치됨, `search_domestic_*_api` +
  `read_source_code`)로 공식 예제의 `COLUMN_MAPPING`을 반드시 먼저 확인할 것 - 이
  MCP는 코드 검색 전용이라 실호출은 못 하지만, 필드명 자체는 신뢰할 수 있는 소스다.
- **단위 혼동에 항상 주의.** 이 코드베이스에는 "억원 단위" vs "원 단위", "백만원" vs
  "원" 혼동으로 인한 버그가 반복적으로 나왔다(`market_cap_eok` 명명 규칙 참고). 새 KIS/
  키움 필드를 쓸 때는 실측값으로 자릿수가 말이 되는지 검증할 것.

### 배포/운영 관련

- **VM에서 스크립트를 재실행하라고 안내하기 전에 항상 `ps aux | grep <script명>`으로
  이미 도는 게 없는지 확인할 것.** 이 세션에서 중복 실행 사고가 5번 이상 났다(사용자가
  명령을 두 번 붙여넣거나, 자동배포 타이머와 겹침). 중복 실행은 같은 캐시 파일을 서로
  덮어써 결과를 예측 불가능하게 만든다.
- **`kill <PID>`가 항상 프로세스를 죽이는 게 아니다.** `nohup ... &`로 띄운 셸 job의
  PID를 죽여도 그 자식 프로세스(실제 `python ...`)가 살아남는 경우가 있었다. `kill`
  직후 반드시 `ps aux`로 재확인할 것.
- **VM 코드 변경 후 라이브로 확인하기 전에 파일이 실제로 배포됐는지 먼저 확인할 것.**
  `grep -n "<새로_추가한_함수명>" ~/kiwoom-api/<파일>.py`로 배포 여부를 확인하고,
  안 됐으면 `sudo systemctl start kiwoom-deploy.service`로 강제 트리거하거나 좀비
  프로세스부터 정리한다(위 1절 참고).
- **FastAPI 새 엔드포인트를 추가한 직후엔 서비스 재시작이 필요하다.** 파일만 배포되고
  `uvicorn` 프로세스가 안 살아나면 404가 계속 난다 - `sudo systemctl restart kiwoom-api`
  로 수동 재시작 후 확인.

### 프론트엔드 관련

- **필드명 충돌에 주의.** 전략검색의 `targetPriceGap` 카테고리는 이미 `targetPrice`/
  `targetGapPct`(업종 배수 기반 자체 계산)를 쓰고 있다 - 나중에 "목표가" 관련 필드를
  추가할 때 이 이름을 재사용하면 서로 다른 계산 결과가 뒤섞인다. 새 계산은 항상
  구분되는 접두어(`analyst*` 등)를 쓸 것.
- **두 요소를 한 줄에 나란히 배치할 때 SVG viewBox 비율이 다르면 높이가 안 맞는다.**
  `width:100%; height:auto`로 반응형 SVG를 쓰는 차트를 컬럼 나누기 하려면, 두 차트의
  viewBox 가로세로 비율을 맞추거나(이번엔 후자를 택함, `FOREIGN_RATIO_H` 신설) 최소한
  같은 폭일 때 결과 높이가 얼마가 되는지 미리 계산해볼 것. 공유 상수(`RATIO_H`)를
  손대면 그 상수를 쓰는 다른 화면(RSI 차트 등)에 의도치 않은 영향이 갈 수 있으니, 필요한
  범위에만 새 상수를 분리할 것.
- **매수/중립/매도처럼 카테고리 합이 전체와 같아야 하는 값은 "기타" 버킷을 반드시
  화면에도 반영할 것.** 분류 안 되는 값을 조용히 버리면 막대그래프 퍼센트 합이
  100%가 안 돼 사용자에게 "정렬이 이상하다"는 오해를 산다.
- Windows Git Bash에서 `python3 -c "..."` 멀티라인 heredoc은 자주 깨진다 - 스크래치패드에
  `.py` 파일을 써서 `python <path>`로 실행하는 편이 안전하다(로컬 진단용). VM 쪽은
  사용자가 직접 터미널에서 실행하므로 `cat > /tmp/x.py << 'EOF' ... EOF` 형태로 안내한다.
