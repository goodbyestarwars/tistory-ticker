## 운영 VM 접근 차단 (2026-10-15 배포 후 확인)
- **운영 VM(GCP us-central1) IP에서 KIND는 모든 요청에 HTTP 403을 돌려준다**(User-Agent와 무관, 메인·목록 모두). 같은 코드가 집 PC(한국 IP)와 GitHub Actions 러너(미국 Azure)에서는 200으로 정상 동작했다. 즉 지역 차단이 아니라 구글 클라우드 대역 차단으로 보인다.
- 현재 운영 상태: `/api/circuit-breaker.market_halt`는 `available=false`, `reason=FETCH_FAILED`(수신 실패)이고 화면은 "자동 확인 불가 · 수신 실패" 회색 표시만 한다(정상으로 보이지 않음).
- 해결 경로(사용자 결정 필요): ① 한국거래소에 사용 동의와 함께 서버 IP 허용 문의, ② 비-GCP 한국/아시아 IP의 소형 서버 또는 프록시(월 수천~만 원대, 신규 인프라), ③ 집 PC에서 수집해 VM에 전달(PC 가동 시간에만 동작, VM 수신 키 필요). 아직 어느 것도 진행하지 않았다.

## 갱신 주기·지연
- 평일(거래일) 08:50~16:10에 **30초마다** 오늘의 공시 목록 1쪽을 확인하고, 새 시장조치 공시마다 본문 3건을 받는다(요청 부담: 평시 2건/분). 재시작 직후에는 하루치(최대 8쪽)를 한 번 받아 이력을 복원한다.
- 공시 게시까지의 지연은 확인하지 못했다(발동 본문 시각과 목록 시각 차이는 실측 1분 이내). 화면 반영 = 공시 게시 + 최대 약 30초. **실시간 체결 데이터가 아니므로 화면에 "공시 기준 · 30초마다 확인 · 실시간 아님"을 항상 표시한다.**
- 수신이 3분 넘게 끊기면(수신 창 안) 이벤트를 비우고 "확인 불가 · 수신 지연"으로 내려간다(정상으로 두지 않음). 장 시작 전·휴장일은 "이벤트 없음", 장 마감 뒤에는 오늘 15:45 이후 성공 수신이 있어야 당일 이력을 신뢰한다.
- 가격 급락만으로 발동을 추정하지 않는다. 공시가 없으면 이벤트도 없다.

## 이용 조건 (확인 결과와 위험)
- KRX 법적고지(`info.krx.co.kr` 06070200): 서비스의 저작권은 한국거래소에 있고, **한국거래소의 사전 동의 없이 복제·전송·출판·배포 등으로 이용하거나 제3자에게 배포할 수 없다**. 정보에 오류·누락·지연이 있을 수 있다는 면책이 있다. KIND에 대한 별도 API 약관·재배포 허락 조항은 찾지 못했다. `robots.txt`는 KIND에서 307(리다이렉트), 정보데이터시스템에서 404였다.
- 그래서 원문을 옮기지 않고 **사실 항목(시장·종류·단계·시각·등락률)만** 쓰고, 화면에 출처와 KIND 링크를 밝힌다. 그래도 공개 대시보드 표시에 대한 명시적 허락이 있는 것은 아니다 - **한국거래소에 사용 동의(또는 정식 시장정보 제공 계약) 문의를 권장**한다. 비용은 KRX 정보상품 안내에서 확인해야 하며 임의로 진행하지 않았다.
- KIND 접근 방식이 바뀌면(응답 형식·차단) `/api/circuit-breaker.market_halt.available=false`(확인 불가)로 내려간다.

## 기존 키움·KIS 보완 가능 여부
KIS 국내주식 API 156개(장운영정보 `H0STMKO0`은 종목별 VI·거래정지 코드뿐)·키움 문서에 시장 전체 사이드카·서킷브레이커 필드가 없어 보완할 수 없다. 장애 시 대체 경로 없음 → 확인 불가 표시.
