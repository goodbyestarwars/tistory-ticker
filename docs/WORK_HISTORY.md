  없다. 이제 ExecStart에 `$`가 하나도 없다.
- 중단한 유닛은 상태까지 로그에 남긴다: `07:30 마감으로 중단: kiwoom-batch(activating)`

검증: `test/test_scan_reaper_behavior.py` 신설 - 가짜 systemctl로 리퍼를 실제 실행해 (1) activating

**2026-09-11 KIS 토큰 만료 처리 - 캐시 수명 보정 + 만료 시 1회 자동 재발급**

2026-09-09 실측에서 `/health/overseas-quote`가 KIS의 `EGW00123`("기간이 만료된 token
입니다")를 반복 반환했다. 같은 시각 같은 서버의 해외 순위 조회는 성공했다 - 워커마다
토큰 캐시가 따로여서 생기는 **간헐 실패**다.

`kis_client.get_token`이 만료를 `now + expires_in`으로만 잡는 게 원인으로 보인다. 이
함수는 "KIS가 짧은 간격 재호출 시 직전 토큰을 그대로 돌려준다"를 전제로 캐싱하는데,
그렇게 **이미 발급된 토큰**을 받으면 실제 남은 수명은 24시간보다 짧다. 캐시는 그걸
모르고 죽은 토큰을 계속 내주고, 만료 에러가 나도 재발급하지 않아 그 워커의 KIS 호출이
전부 실패한다. 화면에서는 미국 종목판 일부 탭이 키움 폴백으로 갈리는 형태로 나타났다.

두 겹으로 고쳤다.

- **캐시 수명 보정**: 응답의 절대 만료 시각(`access_token_token_expired`, KST)이 읽히고
  `now+expires_in`보다 이르면 그쪽을 쓴다. 이 필드의 형식·의미는 리포에서 검증된 값이
  아니므로 **캐시를 줄이는 쪽으로만** 채택하고, 못 읽으면 기존 계산을 그대로 쓴다.
  파싱이 어긋나도 매 호출 재발급으로 번지지 않게 최소 수명 60초를 뒀다(KIS 발급은 분당
  1회 제한).
- **만료 시 1회 재시도**: 공통 호출기(`_get_overseas_rank`, `_get_domestic_quote`,
  `fetch_overseas_price`)가 `EGW00123`으로 실패하면 캐시를 버리고 재발급해 한 번만 다시
  부른다. 호출부는 `get_token`을 한 번 부른 토큰을 여러 조회에 돌려쓰므로 스스로 회복할
  수 없다 - 회복은 여기서만 가능하다. 만료 외 실패는 그대로 올린다. `invalidate_token`은
  실패한 토큰을 인자로 받아 **캐시에 든 값이 그것과 같을 때만** 버린다(동시 실패 시 먼저
  재발급한 스레드의 새 토큰을 뒤늦게 지워 발급을 또 부르는 일 방지).

1번이 틀려도 2번이 있으면 자동 복구된다는 점이 이 구조의 핵심이다.

검증: `pytest test/test_kis_token_cache.py` 9 passed(+7 subtests) - 절대 만료가 캐시를
줄이기만 하는지, 못 읽을 때 폴백, 최소 수명, EGW00123만 재시도 대상인지, 재발급 토큰으로

전체 652 passed(numpy 미설치 8개 모듈 제외, 네트워크 의존 2건 실패는 기존과 동일).

**2026-09-09 미국 종목판 등락률-대비 부호 불일치 수정**

"등락률 기준이 이상해"라는 리포트를 `/market-board?market=us`로 실측했다(15:53 KST).
거래대금 상위 행에서 **대비(change)는 +인데 등락률(change_rate)은 -** 였다.

    SPY  765.96 / diff  4.23 / rate -0.55
    NVDA 225.73 / diff  4.63 / rate -2.01
    MU  1000.26 / diff 16.33 / rate -1.61
    QQQ  718.36 / diff  0.60 / rate -0.08

크기는 맞다 - 225.73/(1-0.0201)=230.36, 230.36-225.73=4.63. 즉 **KIS 해외 순위 응답의
`diff`는 부호 없는 크기이고 방향은 `rate`에만 들어 있다.** `_kis_us_row`가 `diff`를 그대로
`change`에 넣고 있어 하락 종목이 전부 대비 +로 남았다. 화면 여러 곳이 방향은 `change`로,
숫자는 `Math.abs(changeRate)`로 그리므로(`arrowSymbol(change) + Math.abs(changeRate)`)
부호가 어긋나면 하락 종목이 상승 화살표·상승색으로 찍힌다.

`rate`를 방향의 기준으로 삼아 `change` 부호를 맞췄다. 이미 부호가 붙어 오는 키움 폴백
경로(`falling` 실측 NVDA -4.25 / -1.84%)는 결과가 그대로라 손대지 않았다.

같이 확인된 별건(미수정, 사용자 판단 대기):
- `/health/overseas-quote`가 KIS `EGW00123 기간이 만료된 token`을 반복 반환한다. 같은
  시각 순위 API는 성공했으므로 워커별 토큰 캐시 문제로 보인다. `kis_client.get_token`이
  만료를 `now + expires_in`으로 잡는데, KIS는 24시간 안에 재요청하면 **이미 발급된 토큰을
  남은 수명 그대로** 돌려주므로 캐시가 실제 만료보다 늦게 만료된다고 판단한다. 그 사이
  해당 워커의 KIS 호출은 전부 실패한다.
- 같은 응답에서 미국 종목판의 탭별 소스가 갈렸다(`거래대금`은 KIS, `상승·하락·거래량·
  시가총액`은 키움 폴백). NVDA가 탭마다 225.73 / 226.11로 다르게 보인다.

검증: `pytest test/test_market_board_us_symbol.py` 18 passed(신규 5건 - 음수 rate에
diff 부호 맞춤, 상승 행 유지, 이미 부호 붙은 값 이중 반전 없음, diff 없으면 None 유지,
